## macOS 实际窗口观察

使用本机构建的临时应用“Voon Menu Validation”，通过 LaunchServices 显式传入临时索引位置和临时音乐目录；设置界面已显示索引为 `/private/tmp/voon-0003-validation/check.sqlite3`。

已观察到：

- 菜单栏有应用菜单与“资料库”；应用菜单列出“设置…”、“关闭当前窗口”和“退出 Voon”。
- 点击原生“设置…”打开独立设置窗口；`⌘,` 重复打开聚焦同一窗口，`⌘W` 关闭设置后主窗口仍可见，`⌘Q` 退出隔离应用。
- 设置中添加临时音乐目录后完成扫描，主窗口出现 Album A；设置与主窗口使用同一份资料库。
- 忽略规则说明“下次重新扫描生效”可读；重复添加临时目录时，中文错误直接显示在设置窗口。
- “资料库 → 重新扫描”显示当前临时目录；选中后完成增量扫描，主窗口显示“读取 0 个音频文件”，与成功缓存复用一致。
- 集成版本主浏览区不再有常驻设置行，设置窗口中也不再有增量重扫按钮。

尚需补齐：

- 主窗口点击 Album 的自动输入多次只移动指针，无法据此证明浏览选择、编辑草稿与设置交错的可见效果；已请求用户在上述隔离应用手工核对。
- 扫描进行中关闭设置的实际窗口交错、新建索引故障页的完整原生恢复流程、目录菜单随索引切换更新等后续窗口场景。相应状态层保护已受测，但不以状态测试代替窗口结论。

桌面连接首轮单次等待约 42 分钟；用户要求重试后，原生菜单、快捷键和目录选择恢复可用。首次绑定曾显示正常资料库窗口，发现后未对该窗口执行验收操作；随后使用唯一可执行文件名、独立 bundle 与显式临时索引重新启动，并在设置中核对隔离路径后才进行配置操作。

## Linux 验证边界

菜单组件在 macOS 构建中也参与类型检查，仅在 Linux 窗口中呈现。已复用同一应用状态和共享动作，分别挂载在主窗口正常、首次使用、索引故障分支及设置窗口顶部。

当前机器为 macOS arm64，仅有 macOS Rust 标准库；未发现可用的容器运行时或运行中的 Linux 虚拟机，已安装的 Parallels 服务无法连接；仓库没有可执行的远程 Linux 环境约定。因此 Linux X11、Wayland 的构建与实际窗口均保留未验证，04 和 06 不因此宣告完成。
