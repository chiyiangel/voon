# 04: Linux 可见菜单与目录重扫

**What to build:** Linux 用户从窗口顶部实际可见的菜单管理设置与应用窗口，并明确选择音乐目录增量重扫；与 macOS 使用同一套业务操作。

**Blocked by:** [02 独立设置窗口与共享命令](02-separate-settings-window.md)

**Status:** in-progress（代码已接通；Linux 构建及 X11、Wayland 窗口验收待完成）

- [ ] 应用窗口顶部实际显示可操作菜单，提供设置、关闭当前窗口、退出和按目录重新扫描；仅调用保存菜单配置的接口不算交付。
- [x] 菜单动作复用 02 的共享命令、窗口协调和应用状态，不建立独立的 Linux 配置或扫描实现。
- [ ] 显示并支持 `Ctrl+,`、`Ctrl+W`、`Ctrl+Q`；设置窗口重复打开时聚焦，关闭当前设置窗口不退出或停止扫描。
- [x] “资料库 → 重新扫描”使用当前 Library root 列表，单个选择只影响该目录；来源变化后菜单更新，受限和过期动作不能绕过状态保护。
- [ ] Linux 菜单可用后，移除本平台常驻设置行和设置内重扫按钮；保留主窗口扫描反馈、失败重试与专辑强读标签入口。
- [x] 菜单在正常浏览、首次使用及索引不可用状态下可达，不被主内容区的不同分支隐藏（外壳代码已接入，实际 Linux 窗口仍待验证）。
- [ ] 应用状态层回归证明目标目录、配置一致性和保护；Linux 构建及实际窗口验证可见菜单、快捷键、单实例和关闭规则。分别记录 X11 与 Wayland，未验证项不计为通过。
- [x] 平台差异留在应用边界，不修改核心数据库结构或引入托盘常驻。

## 实现与验证记录

- `ui/application_menu_bar.rs` 提供窗口内 Voon、资料库菜单，显示设置 `Ctrl+,`、关闭当前窗口 `Ctrl+W`、退出 `Ctrl+Q`。主窗口与设置窗口各维护展开状态，共享同一个 `AppState`；仅 Linux 呈现此菜单，模块在 macOS 也参与类型检查。
- 重扫子菜单实时读取当前音乐目录；空目录列表、索引不可用、任务进行中及离线目录提供不可执行状态。点击调用共享 `RescanRoot` action，执行时再次经过共享操作的任务、当前目录及离线检查。展开菜单支持 Escape 和点击外部收起。
- macOS arm64：`cargo check -p voon-app` 通过；`cargo test -p voon-app --test rescan --test settings_operations --test library_scan` 的 25 项回归通过，包括指定目录缓存读取、过期目录动作、取消尚未结束的任务保护及配置规则持久化。
- Linux X11：未验证构建、菜单呈现、快捷键、单实例与关闭规则。
- Linux Wayland：未验证构建、菜单呈现、快捷键、单实例与关闭规则。
- 当前环境仅有 macOS Rust 目标，没有 Linux 容器或虚拟机；macOS 的类型检查与状态层回归不替代上述 Linux 窗口证据，因此本票保留 `in-progress`。
- 主 agent 已统一移除旧的常驻设置行和设置内重扫按钮；Linux 可见菜单组件及其外壳代码均已接通，平台行为仍按上述未验证边界记录。

**Demo:** 在 Linux 从可见菜单打开设置，重复命令聚焦；选择一个目录重扫后关闭设置，主窗口继续反馈进度，再由菜单重新打开设置。
