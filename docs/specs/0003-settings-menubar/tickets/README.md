## 实施前沿

初始可开工工单为 **01**。ready-for-agent 表示工单已准备好，不免除依赖条件。

- 01 完成后，02 可开始。
- 02 完成后，03、04、05 可并行；三者互不阻塞。
- 03、04、05 全部完成后，06 可开始。01、02 是传递依赖，不重复列入 06 的 Blocked by。

01 → 02 的依赖来自开放非模态设置窗口前必须具备任务及草稿保护；02 → 03/04/05 的依赖来自共享设置窗口、应用命令与状态。代码位置重叠需要协调，但不据此增加功能阻塞边。

## 通用交付约束

- 每张功能票自带应用操作、状态、界面反馈和定向验证；不把只改接口或只加入口视为交付。局部整理在相应切片开始时完成，不另设纯重构票。
- 01 先在现有设置中补齐保护；02 通过现有入口及快捷键交付独立窗口。各平台菜单可用后，03/04 再移除相应平台旧的常驻设置行和设置内重扫按钮，中间状态始终保留操作入口。
- 主要复用 voon-app 应用状态层，voon-core 公共接口用于配套回归；不新增内部、SQL、像素或截图快照测试接缝。
- 原生菜单、焦点、窗口单实例、关闭与快捷键需实际窗口证据。每票完成自身验证；06 负责完整旅程及交错场景，不能代替前面功能票的基本验证。
- 设置与主窗口共享当前资料库。仅打开或关闭设置保留浏览位置与未提交编辑，关闭设置不退出应用或停止任务；关闭主窗口沿用退出行为。
- Library root 保持只读，使用隔离索引与临时音乐目录验证。本轮不要求重复约 20 张真实专辑验收，也不把 NAS 可用性作为菜单交付前提。
- 备份恢复、旧库迁移、当前数据库搬迁、数据库结构升级、扫描全部目录的新命令、托盘常驻和音乐文件写回不在本轮范围。
- macOS、Linux X11 与 Wayland 的构建及实际窗口结果分别记录；未验证项不计为通过，不能以状态层或其他平台结果替代。02 的 Linux 窗口证据按其验收条目交由 04 核对。
- 开工时更新对应工单及本索引为 in-progress；完成约定验收后更新为 done。代码已实现与平台已验收分别记录，不能据此关闭 0001/0002 的旧验收待办。
