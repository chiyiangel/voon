# 01: 设置操作保护与就地反馈

**What to build:** 用户在现有设置中即可安全增删音乐目录、保存忽略规则和新建索引；扫描中与编辑未提交时的限制有清楚原因，失败无需返回主窗口扫描条才能理解。

**Blocked by:** None (can start immediately).

**Status:** in-progress

- [ ] 普通扫描、失败重试和强读标签进行中，目录增删与新建索引均被应用操作拒绝，界面禁用并显示中文原因；查看设置和保存忽略规则仍可用。
- [ ] 限制在提交前复查；先打开的目录选择器或移除确认不能绕过后来开始的扫描。
- [ ] 专辑编辑或封面选择存在未提交草稿时，新建索引被阻止；当前索引、草稿和已保存资料保留。明确保存或取消后才解除对应限制。
- [ ] 设置操作失败和受限原因在现有设置面板内可见；保留主窗口的扫描进度与扫描问题反馈。
- [ ] 配置即时保存；添加目录成功后启动扫描；忽略规则标明“下次扫描生效”，保存不改变当前任务采用的规则，也不自动重扫。
- [ ] 移除目录仍有确认且不删除音乐文件，保留已保存的编辑、User tag 与 Manual collection；新建索引保留原文件及既有位置、版本检查。
- [ ] 通过已有应用状态层和核心公共接口回归证明拒绝后无资料切换、草稿不丢失、规则生效时机和数据保留；实际界面能看见操作原因。

**Demo:** 启动扫描后打开当前设置，尝试增删目录和新建索引均受限；保存忽略规则后本次任务不变，下次重扫采用新规则。另以状态层场景验证编辑草稿存在时拒绝新建索引。

**User Stories:** 6–8、30–40。
