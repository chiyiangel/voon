# 06: 取消离线与结构整理保持一致

**What to build:** 将完整 Album 发布规则延伸到取消、整根离线、空挂载点以及合并拆分后的重扫，保留原始基线、人工整理和撤销能力，避免过期扫描消息破坏当前状态。

**Blocked by:** [01 局部扫描失败保留完整 Album](01-preserve-complete-albums.md)

**Status:** done

- [x] 取消首次扫描保留完整发现部分；取消重扫保留未访问 Album，重开后仍可浏览。
- [x] 扫描期间根目录消失或设备变化时不清空旧索引；正常根的更新不受另一根失败影响。
- [x] 曾有内容的根本次为空时继续要求明确确认，确认前不更新完整基线。
- [x] 不完整范围不推断 Rename candidate，也不污染下一轮完整扫描的改名判断。
- [x] 合并拆分结果、真实来源、组织关系及撤销记录经局部失败后保持可用。
- [x] 扫描期间的新人工编辑继续优先，取消、切换任务或移除根之后的过期事件不重新发布旧状态。
- [x] core 与 GPUI 状态层覆盖取消、离线、重新连接及结构操作交错的可观察结果。

## 实现与验证记录（2026-11-11）

- 公共提交接口自动尊重取消状态；根目录覆盖未确认的结果只能增量提交。`ScanCoverage.unvisited_paths` 记录取消略过的范围，目录事件触发取消时不发布尚未完整访问的父 Album。
- 首次扫描保留的完整发现也纳入空根保护。取消后可直接切换另一个扫描任务：先持久保存已接受发现，再关闭旧接收端隔离晚到消息；意外 worker 失败/断开同样保存完整发现。
- 尚未来得及上报的 Collection 链从已完整发现 Album 的 Collection 关系补齐。部分重试只解除已完整重新观察 Album 的失败；同位置的新一轮问题替换旧原因，并保留本轮全部 CUE 失败。
- 不完整扫描不推进完整改名基线、不新增改名候选；独立确认移除/变化仍会使已经失效的旧候选过期。目录项 stat 失败精确记录到该项，失效专辑链接不会阻断同根正常专辑更新。
- TDD red→green 依次验证：取消结果经普通提交误删未访问 Album；取消后晚到专辑仍发布；取消后未观察完整的父 Album 仍发布；首次部分扫描后的空根误清空；其他位置失败使过期改名候选残留；取消重试不解除已恢复错误；无覆盖记录的结果误确认缺失；取消后不能切换任务；worker 中断丢失完整发现；多个 CUE 错误只保留最后一条；失效链接阻断独立 Album 更新。
- 独立 `CARGO_TARGET_DIR=/private/tmp/voon-0002-implementation/scan-target`：core `scan_integrity / scan / library_roots / rename_and_loose / album_structure / attention / ignore_rules` 共 50 项通过；GPUI `library_scan / rescan / album_structure` 共 17 项通过。工作区离线 check、严格 Clippy（含全部测试目标）、格式和差异检查通过。未运行全工作区测试，由最终集成统一执行。
- 合并经局部失败、重开后仍保持两份真实来源并可撤销；按碟拆分后缺一碟的扫描也保留两个结果及撤销。状态层覆盖离线/重新连接、取消后多根切换与扫描期间保存的编辑。
- 无新增数据库迁移。测试使用临时故障库和受控不可用事件；实际设备切换、真实 NAS 断连、窗口和 Linux/Wayland 验收保留给工单 11，未以状态测试替代平台结论。

**Demo:** 合并一张多碟专辑后重扫，中途断开或取消，再重开并重新连接；专辑结构和编辑仍在，撤销可用且没有假改名。
