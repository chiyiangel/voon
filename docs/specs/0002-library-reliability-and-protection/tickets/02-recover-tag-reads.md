# 02: 标签失败分类与增量恢复

**What to build:** 一次标签读取失败不会清空上次成功资料，也不会被相同 stamp 的缓存长期阻止重试。普通重扫可在读取恢复后补齐元数据，界面能区分无标签、未支持、暂时失败和解析失败。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-agent

- [ ] 成功有数据、成功无标签、未支持格式、暂时 I/O 失败和解析失败具有可观察的不同结果。
- [ ] 失败记录与上次成功资料分开保留；失败不把已有元数据覆盖成空值。
- [ ] 相同大小和修改时间下，下一轮普通重扫实际重试失败读取，成功后解除错误。
- [ ] 成功且未变化的标签仍复用缓存；未支持格式不进入无限自动重试。
- [ ] 详情或 Needs attention 显示中文路径、阶段和原因，不依赖新增的手动重试按钮才能验证普通重扫恢复。
- [ ] 保留真实读取时间和成功缓存的来源关联，命中缓存不伪造新观察；在两个既有接缝验证关闭重开和恢复行为。

**Demo:** 首次读取失败，保持源文件不变，再恢复读取并普通重扫；底层实际重读一次、资料补齐，第三次未变重扫不再重读成功标签。

**User Stories:** 22–27、30、44。
