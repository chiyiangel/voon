# 04: 当前 Cover 持久化与离线重开

**What to build:** 现有浏览或封面选择流程成功加载的当前 Cover 写入本机持久缩略图，退出后断开 NAS 仍可显示；自动图和手选图使用同一套关联与失效规则。

**Blocked by:** 无（可立即开始）

**Status:** done

- [x] 外置图片、内嵌图片及指定内嵌索引都能生成可重开的本地缩略图。
- [x] 资产完整写入并可读取后才标为已就绪，持久数据及其 Cover 关联经应用重开保留。
- [x] 已就绪封面在退出进程、断开来源、重新启动后仍可在网格和详情显示。
- [x] 更换选择或确认来源变化时更新关联；迟到任务不能覆盖较新的选择。
- [x] 单项读取、解码或缓存损坏不清空 Album、选择或其他资产；无有效缓存时不冒充已就绪。
- [x] 内存淘汰不删除应保留的持久资产；后台工作有界，产物不写入 Library root。
- [x] 用真实图片、真实本地存储和重开场景验证，不只让假加载器返回成功。

**Demo:** 浏览几张自动封面并手选一张内嵌图片，待加载成功后退出、断 NAS、重启；这些图片仍能显示。

**User Stories:** 56、59–63、65–67。

**切片边界:** 本票把现有“已请求的封面”流程变为可持久使用；全部未浏览 Album 的后台覆盖和全局进度在 [10 全库封面预缓存与失败重试](10-library-cover-prefetch.md)交付。

规格：[0002 资料库扫描可靠性与离线浏览](../../0002-library-reliability-and-protection.md)。通用约束与实施前沿见[工单索引](README.md)。

## 实施与验证记录（2026-11-11）

- 按已批准 AppState 接缝先加入真实 PNG 的持久化与离线重开测试，首次运行因缺少公开缩略图接口失败；实现后通过。真实资产回归另覆盖 DSF 自动封面、指定第二张内嵌图、来源变化、迟到请求、单张本地损坏、写入失败及 260 张图片超过内存容量后重开。
- 缩略图与完整 Cover/来源 stamp 的关联写入 `<index 文件路径>.covers-v1/`，无需数据库结构迁移。PNG 和关联分别通过暂存文件原子发布；仅当本地图片已完整写入、同步并成功读取解码后报告就绪。失效任务不发布关联。内容键校验可识别被替换为另一张有效图片的本地资产：该回归先复现未失败状态的 red，补齐校验后 green。
- 网格、列表与详情保留共享 CoverCache API，委托 AppState 的同一有界队列处理；最多 4 项后台读取/解码/写入，最多 256 张解码图驻留。内存淘汰不删除持久图片。失败提示与无封面分开，详情显示来源/本地写入原因。
- 独立构建目录 `/private/tmp/voon-0002-implementation/covers-target`，定向命令：`cargo test -p voon-app --test persistent_covers --test album_grid --test cover_picker --locked --offline`；7 项新资产测试与 4 项既有回归通过。`cargo check --workspace --locked --offline`、严格 app Clippy、格式和 diff 检查通过。
- 未访问真实 NAS、用户数据库或真实 Voon 窗口。这里验证关闭并重建 AppState/Index 的离线行为；实际进程退出后的窗口验收、真实样本和 Linux/Wayland 结论保留在 11，不以状态测试代替。全库未浏览 Album 的主动覆盖由 10 继续交付。
