# 05: 新建索引与资料库版本保护

**What to build:** 用户可保留原库、从新建资料库扫描；已有未知或较新版本的库得到中文提示，在任何写入性初始化之前拒绝改写。

**Blocked by:** 无（可立即开始）

**Status:** in-progress

- [x] 新库能创建、扫描、重新打开并继续正常使用。
- [x] 已有更高结构版本或无法识别身份的库，在写入性初始化及迁移前被拒绝。
- [x] 拒绝不会改写原库及已有相关文件，也不自动降级、清空或把未知库当成空库。
- [ ] 不兼容提示可见且可理解，说明保留原库、新建索引重新扫描的选择。
- [x] 旧库文件不因创建新库而被删除或覆盖，不增加旧库迁移和来源补齐流程。
- [x] core 公共接口验证文件不变与新库往返，应用状态验证相应可见提示和新建流程。

**Demo:** 选择一个未知库或较新库，看到拒绝说明且原文件不变；随后从新库扫描成功。

**User Stories:** 1、2、68–71。

## 实施与验证记录

- 核心 red → green：较新版本曾被直接接受；未知但版本号相同的 SQLite 文件也曾被当作 Voon 库接受。现在先只读原文件到自动清理的临时检查副本，连同已有 WAL/SHM/journal 检查身份与版本，再允许原库进入写入性初始化。检查副本不迁移、不保留为备份。
- 新库写入独立的 SQLite `application_id`；结构版本仍取现有迁移数。既有无身份标记库仅按相应迁移前缀的完整结构识别，保留原 v2 迁移代码和测试，不增加历史资料补齐流程。
- 公开接口 `Index::create` 以独占新建拒绝覆盖已有文件及 sidecar；测试覆盖新建、扫描、重开和继续增量扫描。高版本主文件、实时 WAL 中的新版本、符号链接的真实目标、未知 SQLite、空文件和非 SQLite 文件均核对拒绝前后字节、文件集合和修改时间不变。符号链接场景曾 red，解析真实目标后 green。
- AppState red → green：启动失败进入可见中文状态，拒绝在占位内存库开始扫描；用户可保留原库创建新索引，并原子保存所选位置，重开恢复所选库和扫描成果。新增本地索引不能写入建议的音乐库位置。
- 默认本轮索引为 `library-0002.sqlite3`，保留既有 `library.sqlite3`；本机位置选择记录为 `current-index-path`。开发与假库验收可设绝对 `VOON_INDEX_PATH`，该覆盖不会读取或改写用户 AppSupport 索引及位置选择记录。
- 定向验证：core `index_protection` 6 项、既有 `migrations` 1 项；AppState `index_startup` 3 项及 `app_state` 4 项、`library_scan` 3 项。工作区离线编译、严格 Clippy、格式与差异检查通过。
- 尚未启动实际 Voon 窗口、调用真实原生文件选择器或访问真实用户库/NAS；窗口和 Linux/Wayland 验收留给总任务，状态保留 `in-progress`。
