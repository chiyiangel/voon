# 10: 全库封面预缓存与失败重试

**What to build:** 将持久封面能力扩到所有已入库 Album，不要求逐张浏览；独立显示预缓存进度，区别无图、未缓存、处理中、已就绪和失败，并能重试失败封面。

**Blocked by:** [04 当前 Cover 持久化与离线重开](04-persistent-cover-thumbnails.md)

**Status:** ready-for-agent

- [ ] 扫描接受或加载全部 Album 后，当前自动和手选 Cover 都进入后台缓存，不依赖视口请求。
- [ ] 缓存任务有界，不为全库常驻全部解码图像，内存淘汰不删除当前封面的持久资产。
- [ ] 扫描进度与封面进度分开；存在失败或尚未完成时不声称全部封面已就绪。
- [ ] 单项失败显示明确状态，来源恢复后可重试，不必重扫全部音乐。
- [ ] 更换封面、移除根或出现过期任务时，状态和最终图片对应最新有效选择。
- [ ] 未浏览 Album 及超过内存容量的封面，在缓存就绪后退出、断 NAS、冷启动仍可显示。
- [ ] 用真实本地资产和 GPUI 状态证明全库队列、失败恢复及离线加载，另做进程冷启动窗口验证。
- [ ] 不扩展为小册子、原图收藏、历史封面管理或 Library backup。

**Demo:** 不逐张浏览便让一批专辑封面缓存完成，包含一张故障图；恢复来源并重试，再冷启动离线查看未浏览过的专辑。

**User Stories:** 4、55–67。

规格：[0002 资料库扫描可靠性与离线浏览](../../0002-library-reliability-and-protection.md)。通用约束与实施前沿见[工单索引](README.md)。
