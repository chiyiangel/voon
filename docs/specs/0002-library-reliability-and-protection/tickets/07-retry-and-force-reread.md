# 07: 重试失败项与强制重读标签

**What to build:** 用户可以从失败状态重试相关项，或对选中 Album 强制重读标签；操作有明确进度、有限的一轮工作和取消能力，不影响无关成功资料。

**Blocked by:** [01 局部扫描失败保留完整 Album](01-preserve-complete-albums.md)；[02 标签失败分类与增量恢复](02-recover-tag-reads.md)

**Status:** in-progress

- [x] 目录和标签失败记录提供匹配的重试入口，相关 Library root、Album 与阶段明确。
- [x] 失败项重试不把整个资料库无差别重新读取，成功后对应状态解除。
- [x] 强制重读绕过选中 Album 的相关标签缓存，其他成功且未变的缓存仍有效。
- [x] 取消后保留已接受的完整资料；临时失败不清空上次成功值。
- [x] 每次触发只执行有限一轮，不创建持续监听、定时扫描或无限重试服务。
- [x] GPUI 状态层验证“操作—实际读取—持久化—状态解除”及取消；所有交互保持中文。

**Demo:** 在 Needs attention 中重试一个已恢复的目录，再对一张专辑强制重读，核对只处理预期范围并能取消。

**User Stories:** 13、23、24、28、29、31、32、72。

## 实施与验证记录

- 复用已批准的 core 公开接口与 GPUI AppState 接缝。强读、精确标签重试和散音频更新各有 red → green；旧读取阻塞、新读取成功、旧失败迟到的并发公开场景也先复现覆写，再修复。
- `CachedTags::with_forced_paths` 只绕过指定音频；`TagReader::observe` 可明确省略未请求且尚无观察的来源，不把省略伪报为成功无标签。普通增量缓存策略保持原语义，缓存命中不刷新观察时间。
- `Scanner::start_request` 默认转发旧 `start`，保留已有受控扫描器兼容；真实 worker 仍有限遍历相关 root 的结构，仅在请求范围实际读取标签，其余来源复用已有观察。实体 Album 与目录重试以相关完整结果作部分提交，不把筛选结果当成完整 root 空快照。
- 根目录散音频按标签合成分组，强读此类来源在完整覆盖后按本轮完整结构提交，使已失效旧分组正常消失；取消或目录不完整仍按 06 保留规则处理。不新增身份迁移，人工资料继续按原路径保留。界面提前提示分组可能变化。
- 选中合并 Album 按全部 Track 的实际音频来源组成有限多根队列；取消终止整轮，失效接收器隔离沿用 06。详情与待处理均提供相应失败重试，详情提供强读入口，横幅区分扫描、重试和强读及实际读取数。
- 追加 `tag_observation.read_started_at` 迁移，实际读取开始时分配顺序，条件写入拒绝旧任务迟到结果；来源 `observed_at` 仍为真实读取时间，未被缓存命中伪造。旧读取被拒绝后返回已保存的新观察。
- GPUI 使用有效本地 PCM WAV 验证强读 1 文件、同 Album 单失败重试 1 文件且保留另一失败、跨 root 合并来源 2 文件、取消整轮、散音频失效分组及人工资料重现。原增量计数测试的损坏 FLAC 占位改为有效 WAV，继续断言首次 2、未变 0、单文件变化 1，避免把正确的解析失败重试误判为缓存回归。
- 定向验证：core 标签恢复、散音频与改名、版本保护及历史迁移；AppState 标签刷新 5 项、重扫 9 项、待处理 3 项、详情 6 项。工作区 `check`、库/二进制及本票定向测试的严格 Clippy、格式与差异检查通过。此隔离基线的全目标 Clippy 被另票封面测试中两处旧 `Album` 构造缺少 `candidates` 阻断，已通知总任务在集成主分支处理，未混入本票。
- 未启动真实 Voon 窗口、未访问真实 NAS、未修改用户数据库；实际可见行为和平台联验由总任务继续，因此状态仍为 `in-progress`。
