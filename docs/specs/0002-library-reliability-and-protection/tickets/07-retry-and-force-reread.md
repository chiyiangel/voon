# 07: 重试失败项与强制重读标签

**What to build:** 用户可以从失败状态重试相关项，或对选中 Album 强制重读标签；操作有明确进度、有限的一轮工作和取消能力，不影响无关成功资料。

**Blocked by:** [01 局部扫描失败保留完整 Album](01-preserve-complete-albums.md)；[02 标签失败分类与增量恢复](02-recover-tag-reads.md)

**Status:** ready-for-agent

- [ ] 目录和标签失败记录提供匹配的重试入口，相关 Library root、Album 与阶段明确。
- [ ] 失败项重试不把整个资料库无差别重新读取，成功后对应状态解除。
- [ ] 强制重读绕过选中 Album 的相关标签缓存，其他成功且未变的缓存仍有效。
- [ ] 取消后保留已接受的完整资料；临时失败不清空上次成功值。
- [ ] 每次触发只执行有限一轮，不创建持续监听、定时扫描或无限重试服务。
- [ ] GPUI 状态层验证“操作—实际读取—持久化—状态解除”及取消；所有交互保持中文。

**Demo:** 在 Needs attention 中重试一个已恢复的目录，再对一张专辑强制重读，核对只处理预期范围并能取消。

**User Stories:** 13、23、24、28、29、31、32、72。

规格：[0002 资料库扫描可靠性与离线浏览](../../0002-library-reliability-and-protection.md)。通用约束与实施前沿见[工单索引](README.md)。
