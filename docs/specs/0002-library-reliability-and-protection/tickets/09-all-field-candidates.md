# 09: 全部现有字段的候选与编辑一致性

**What to build:** 将已可使用的候选比较扩到全部十个现有专辑字段，保持离线查询、失败来源保留、人工覆盖及现有浏览组织的一致性。

**Blocked by:** [08 标题与年份的完整来源比较](08-title-and-year-candidates.md)

**Status:** done

- [x] 其余现有字段接入同一来源保存、公开查询、详情比较和恢复自动值行为，不新增领域实体或字段种类。
- [x] 合辑中少数曲目的作曲家、演奏者等候选不因多数值归并而丢失，仍保留具体文件与曲目范围。
- [x] 默认自动值及人工优先级不变，已保存人工资料经普通和强制重读继续保留。
- [x] 失败来源沿用上次成功候选及状态，成功重读后更新；重新打开后仍可离线比较。
- [x] 流派维持仅来自 Metadata tag，乐团没有自动来源时保持未知或使用人工值，不编造资料。
- [x] 列表、详情、既有作曲家浏览及编辑对同一采用值保持一致。
- [x] 不引入逐字段来源偏好、显式人工空值、多年份模型、在线查询或批量冲突审阅。
- [x] 两个既有接缝覆盖全部字段及组织、结构操作回归，必要的真实窗口验收核对候选可读性。

**Demo:** 打开含不同作曲家和演奏者的合辑，所有候选可查；断 NAS、编辑并恢复自动值，重开后来源与选择一致。

**User Stories:** 33–47、75（全部字段范围）。

规格：[0002 资料库扫描可靠性与离线浏览](../../0002-library-reliability-and-protection.md)。通用约束与实施前沿见[工单索引](README.md)。

## 实施与验证（2026-11-11）

- 全部十个字段使用同一比较读模型与详情入口，保留未获多数票的文件候选。流派仅来自标签，乐团仍由人工编辑提供。
- 标签、目录和 CUE 的来源说明保留具体路径及曲目范围；同一映像的另一份有效 CUE 也可比较，自动值仍沿用第一份参与解析的分轨表。
- 合并、拆分后按当前 Track 范围筛选和合并相同来源；撤销仍能恢复原候选。目录失败时旧候选显示未重新确认，不制造新的读取时间。
- core candidates 6 项通过，覆盖少数作曲家、全部字段、失败保留、另一 CUE、编辑恢复与结构往返；GPUI candidates 2 项、composer_browse 1 项、album_structure 2 项通过。核心结构 12 项与扫描 8 项回归通过。
- check、fmt、diff-check 通过。真实窗口可读性、强制重读与全链路交错继续在 11 联验。
