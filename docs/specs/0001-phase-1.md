# Voon 第一期规格（Phase 1）

术语以仓库根目录的 GLOSSARY 为准：Library root、Collection、Manual collection、Album、Disc、Track、Whole-disc image、CUE sheet、Virtual track、Cover、Metadata tag、User tag、Facet、Field source、Loose audio、Content signature、Rename candidate、Needs attention（待处理）。正文中这些词保持英文原样。相关决策见 ADR 0001–0004。

## 问题陈述（Problem Statement）

我（Mobert）的音乐收藏放在 NAS 上，通过 SMB 挂载在 /Volumes/NAS1/Music，大约 450 GB、707 个专辑目录、5600 多个文件。格式很杂：FLAC、APE、DSF、DFF、WavPack、WAV 都有，DSD 约 100 GB。

整理起来难在这几点：

- 大约 527 张碟是"整轨 + CUE"：一个 CDImage.ape 或 .flac 配一个 .cue。在普通文件浏览器里，一张专辑就是一个大文件，看不到曲目。CUE 的编码也五花八门，UTF-8、带 BOM 的、GBK、Shift-JIS 都有，打开经常是乱码。
- 目录组织没有统一规则。大多数是一个文件夹一张专辑，但也有"演奏家/专辑"两层的。还有 Philips Duo 这种套装，外层 193 个子目录，每个下面再分 CD1、CD2、Booklet。
- 专辑信息大量写在目录名里：年份 (1988)、规格 [24-96]、[DSD64]、[FLAC24bit96kHz]、唱片编号 [438317-2]、版本 [台湾首版]。另一方面，有的文件名只有一串数字（0015830558.flac），只能靠 Metadata tag 或 CUE 才知道是什么。
- 中文、日文、英文名字混在一起。古典乐占比高，我想按作曲家、演奏者、指挥来找，但普通播放器只认"艺术家"。
- 目录里混着小册子扫描、.log、广告 .url、.DS_Store、群晖的 @eaDir 和 #recycle，干扰浏览。
- 这批收藏很多是 CD 抓轨和套装，丢了很难再找到。我不放心让任何工具批量改名或改标签。

我要的是一个桌面软件：先把这个库看清楚、整理清楚，所有整理结果都放在软件自己的数据库里，而且 NAS 没挂载的时候也能浏览。

## 解决方案（Solution）

Voon 是一个 macOS 和 Linux 桌面应用，界面只有中文。

我添加一个或多个 Library root 后，Voon 在后台扫描。扫描时 Album 一张张出现在界面上，随时可以取消。Voon 会自动判断哪些文件夹是 Album，哪些子文件夹是 Disc，哪些外层文件夹是 Collection。整轨加 CUE 会显示成 Virtual track，原文件不切。封面会自动识别。

专辑信息从 Metadata tag、CUE sheet、目录名三处汇总，每个字段都标明来源。我在 Voon 里改过的值永远优先，也可以随时恢复成自动值。

我可以按以下方式浏览和筛选：
- Collection
- 作曲家
- Facet：格式、采样率/位深、DSD 还是 PCM、语种、年代、流派
- 我自己的 User tag 和 Manual collection

拿不准的情况都会进"待处理"，每条写明原因，例如：
- 可能是改名或移动过的文件夹
- 根目录下没有专辑标签的散文件
- 专辑里套着专辑
- CUE 指向的文件不存在
- 标题只能从目录名推断

我可以修改专辑级字段、合并或拆分 Album、选择封面。

Voon 不播放音乐，只提供"用默认播放器打开"。Voon 对 NAS 只读，从不修改库里的任何文件。

界面布局按已出的三栏高保真原型来做（2026-11-11 Mobert 已确认按现有原型开始实现）。第一期结束时打包成带图标的 macOS .app。

## 用户故事（User Stories）

### 音乐库与扫描

1. 作为收藏者，我希望添加 /Volumes/NAS1/Music 作为 Library root，以便 Voon 开始整理我的 NAS 音乐。
2. 作为收藏者，我希望添加多个 Library root（例如 NAS 一个、本机一个），以便在同一个界面里管理所有收藏。
3. 作为收藏者，我希望移除一个 Library root，以便不再显示它下面的 Album。移除时我希望明确知道我的编辑会不会保留。
4. 作为收藏者，我希望首次扫描在后台进行，以便扫描几百张专辑时界面仍然可以操作。
5. 作为收藏者，我希望扫描时 Album 一张张出现，以便不用等全部扫完就能开始浏览。
6. 作为收藏者，我希望看到扫描进度（当前目录、已发现的 Album 数），以便知道还要等多久。
7. 作为收藏者，我希望随时取消扫描，并保留已经找到的 Album，以便在 NAS 很慢时及时止损。
8. 作为收藏者，我希望之后重新扫描只读取大小或修改时间变了的文件，以便几千个文件的重扫在几秒到几十秒内完成。
9. 作为收藏者，我希望能手动触发某个 Library root 的重新扫描，以便在 NAS 上加了新专辑后马上看到。
10. 作为收藏者，我希望扫描期间某个目录读取失败时，扫描能继续进行，并把该目录列入待处理，以便一个坏目录不影响整体。
11. 作为收藏者，我希望 NAS 没挂载时照样能浏览、搜索和编辑，以便出门在外也能整理。
12. 作为收藏者，我希望 NAS 未挂载时界面明确提示"音乐库目录不存在或未挂载"，而不是显示一个空库，以便我知道数据还在。
13. 作为收藏者，我希望扫描自动跳过 .DS_Store、._ 开头的文件、@eaDir、#recycle 这类杂项，以便它们永远不会出现在界面上。
14. 作为收藏者，我希望在设置里查看内置的忽略规则，并添加我自己要忽略的文件夹，以便排除临时目录或不想管理的子树。
15. 作为收藏者，我希望小册子 PDF、.log、.m4v、广告 .url 等非音乐文件被忽略，只有封面图片会被识别，以便界面只围绕音乐。

### Album、Disc 与 Collection 的识别

16. 作为收藏者，我希望含有音频的文件夹被识别为一张 Album，以便大多数"一个文件夹一张专辑"的情况开箱即用。
17. 作为收藏者，我希望 CD1、CD 02、Disc 2、disk3、第2碟 这类子文件夹被识别为同一张 Album 的 Disc，以便多碟专辑显示为一张专辑。
18. 作为收藏者，我希望 Disc 按文件夹里的编号排序和编号，以便 Disc 1、Disc 2、CD 03 的顺序正确。
19. 作为收藏者，我希望 Booklet、Scans、Artwork、扫图 这类子文件夹被当作附件目录而不是 Disc 或 Album，以便小册子不干扰专辑结构，但其中的封面仍然可以使用。
20. 作为收藏者，我希望只包含 Album 的文件夹（Philips Duo、Alfred_Brendel）被识别为 Collection，以便按套装或演奏家分组浏览。
21. 作为收藏者，我希望 Collection 可以嵌套，以便"系列/子系列/专辑"这种结构如实呈现。
22. 作为收藏者，我希望专辑文件夹里又套了一个专辑文件夹时，两张 Album 都保留，同时外层专辑列入待处理，以便我自己决定怎么处理。
23. 作为收藏者，我希望直接放在 Library root 下的散音频，按 Metadata tag 里的专辑名和专辑艺术家分组成 Album，以便散落的单曲也能归到正确的专辑。
24. 作为收藏者，我希望根目录下没有专辑标签的散音频，逐个列入待处理，而不是被塞进一张虚构的专辑，以便我知道哪些文件需要补信息。
25. 作为收藏者，我希望 Library root 下直接放着的 CD1 文件夹被当作一张独立的 Album，以便根目录结构异常时不会把整个库误判成一张专辑。

### 整轨与 CUE sheet

26. 作为收藏者，我希望"一个 Whole-disc image 加一个 CUE sheet"显示为多首 Virtual track，以便像普通专辑一样看到曲目表。
27. 作为收藏者，我希望 Virtual track 带有 CUE 里的曲名、演奏者和时长，以便不用打开 CUE 文件。
28. 作为收藏者，我希望 GBK、Shift-JIS、UTF-8（带或不带 BOM）、UTF-16 编码的 CUE 都能正确显示中日文，以便不再看到乱码。
29. 作为收藏者，我希望 CUE 里写的是 CDImage.wav、实际文件是 CDImage.ape 或 .flac 时，Voon 仍能找到对应文件，以便常见的"抓轨后压缩"不会出错。
30. 作为收藏者，我希望同一个文件夹里有 CD1.cue/CD1.flac 和 CD2.cue/CD2.flac 两组时，它们成为同一张 Album 的两张 Disc，以便双碟整轨显示正确。
31. 作为收藏者，我希望同一个映像有两份 CUE（例如一份 GBK、一份 UTF-8）时只计一次，以便曲目不会重复。
32. 作为收藏者，我希望"每首一个文件"的 CUE 只提供曲名，文件仍然作为普通 Track，以便分轨专辑也能用上 CUE 里的曲名。
33. 作为收藏者，我希望 CUE 指向的文件不存在时，这条问题列入待处理，并写明是哪个 CUE、找不到哪个文件，以便我去修复。
34. 作为收藏者，我希望没有任何曲目的 CUE 列入待处理，以便发现损坏的 CUE。
35. 作为收藏者，我希望 Voon 永远不切分整轨文件，以便 NAS 上的原文件保持原样。

### 专辑信息与 Field source

36. 作为收藏者，我希望专辑标题、专辑艺术家、年份、流派、唱片编号、版本等字段，自动从 Metadata tag、CUE sheet 和目录名汇总，以便大部分专辑无需手动录入。
37. 作为收藏者，我希望多个来源不一致时按"我的编辑 > Metadata tag > CUE sheet > 目录名"取值，以便结果可预测。
38. 作为收藏者，我希望在专辑详情里看到每个字段的 Field source（标签 / CUE / 目录名 / 我的编辑），以便判断这个值可不可信。
39. 作为收藏者，我希望从目录名里解析出年份、格式、采样率/位深、DSD 倍率、唱片编号和版本备注，例如 (1988)、[24-96]、[DSD64]、[FLAC24bit96kHz]、[96kHz/24bit]、[438317-2]、[UCCG-1234]、[台湾首版]，以便目录名里的信息不被浪费。
40. 作为收藏者，我希望目录名中无法识别的括号内容（例如 (Live)）留在标题里，以便不会误删信息。
41. 作为收藏者，我希望"艺术家 - 专辑名"形式的目录名能拆出艺术家和标题，作为最低优先级的候选，以便没有标签的专辑也有基本信息。
42. 作为收藏者，我希望流派只从 Metadata tag 读取，不从 CUE 或目录名猜测，以便流派分类干净。
43. 作为收藏者，我希望修改任意专辑级字段后，我的值立即覆盖所有自动来源，以便我的整理结果说了算。
44. 作为收藏者，我希望一键把某个字段恢复为自动值，以便改错时能回退。
45. 作为收藏者，我希望我的编辑在每次重新扫描后都保留，以便不会因为重扫丢失工作。
46. 作为收藏者，我希望只能从目录名得到标题的 Album 列入待处理，并注明"标题仅来自目录名"，以便我优先补全这些专辑。
47. 作为收藏者，我希望 FLAC、APE、WavPack、WAV、AIFF、MP3、M4A、AAC、Ogg、Opus 的 Metadata tag 和音频属性（采样率、位深、声道、时长）都能被读取，以便 Facet 和详情准确。
48. 作为收藏者，我希望 DSF 文件里的 ID3v2 标签（曲名、艺术家、专辑、专辑艺术家、曲号/碟号、年份、流派、作曲家、内嵌封面）和 DSD 采样率都能被读取，以便 DSD 专辑和 PCM 专辑享受同等待遇。
49. 作为收藏者，我希望 DFF 文件在第一期至少能凭扩展名和目录名被识别为 DSD，并使用 CUE 和目录名的信息，以便它们不会消失。

### 古典音乐

50. 作为古典乐听众，我希望 Album 有作曲家、演奏者、指挥、乐团这几个专辑级字段，以便准确描述一张古典唱片。
51. 作为古典乐听众，我希望作曲家、指挥从 Metadata tag 或 CUE 自动填入，演奏者取各曲艺术家去重后的集合，以便少打字。
52. 作为古典乐听众，我希望手动填写乐团（第一期没有自动来源），以便关键信息完整。
53. 作为古典乐听众，我希望按作曲家浏览，看到每位作曲家名下的全部 Album，以便快速找到"所有莫扎特"。

### 浏览与搜索

54. 作为收藏者，我希望界面采用左侧导航、中间专辑列表、右侧详情的三栏布局，以便浏览和查看同时进行。
55. 作为收藏者，我希望专辑列表可以在封面网格和列表视图之间切换，以便既能看封面也能看信息密度更高的表格。
56. 作为收藏者，我希望按标题、艺术家、年份、加入时间排序，以便按我的习惯浏览。
57. 作为收藏者，我希望按标题、艺术家、作曲家、唱片编号搜索，中英日文都能搜到，以便在 700 张专辑里快速定位。
58. 作为收藏者，我希望在左侧导航里展开 Collection 层级，点击某个 Collection 只显示其中的 Album，以便浏览 Philips Duo 这类套装。
59. 作为收藏者，我希望列表里显示 Collection 名、Disc 数和 Track 数，以便一眼看出套装和多碟专辑。
60. 作为收藏者，我希望在几千条记录下滚动依然流畅，以便大库也好用。

### Facet 筛选

61. 作为收藏者，我希望按格式（FLAC、APE、DSF、DFF、WavPack 等）筛选，以便找出某种格式的专辑。
62. 作为发烧友，我希望按分辨率等级（有损、CD 规格、Hi-Res、DSD64/128/256/512）筛选，以便专门浏览高解析度收藏。
63. 作为发烧友，我希望按最高采样率和位深筛选（例如 24/96 及以上），以便精确挑选。
64. 作为发烧友，我希望按 DSD / PCM 筛选，以便区分两类录音。
65. 作为收藏者，我希望按语种（中文、日文、韩文、西文）筛选，语种根据标题和艺术家的文字自动判断，以便分开浏览华语和日语唱片。
66. 作为收藏者，我希望按年代（1950s、1980s……）筛选，以便按时代浏览。
67. 作为收藏者，我希望按 Metadata tag 中的流派筛选，以便沿用已有的流派信息。
68. 作为收藏者，我希望多个 Facet 可以组合筛选，并显示每个取值下的专辑数，以便逐步缩小范围。

### User tag 与 Manual collection

69. 作为收藏者，我希望给 Album 加上自定义 User tag（例如"华语经典"），以便按自己的方式分类。
70. 作为收藏者，我希望一次给多张 Album 批量加或去 User tag，以便整理效率高。
71. 作为收藏者，我希望按 User tag 浏览，以便快速找到打过标签的专辑。
72. 作为收藏者，我希望重命名或删除一个 User tag，以便维护标签体系。
73. 作为收藏者，我希望创建 Manual collection（例如"周末"），把任意 Album 加进去，以便组建不受目录结构限制的歌单式合集。
74. 作为收藏者，我希望调整 Manual collection 内的顺序、移除其中的 Album、重命名或删除整个 Manual collection，以便长期维护。
75. 作为收藏者，我希望 User tag 和 Manual collection 不写入任何文件，只保存在 Voon 的数据库里，以便 NAS 不受影响。

### 专辑详情

76. 作为收藏者，我希望在详情面板看到封面、全部专辑级字段及其 Field source、User tag、所属 Collection 和 Manual collection，以便集中查看一张专辑的全部信息。
77. 作为收藏者，我希望多碟专辑的曲目按 Disc 分组显示，以便分清每张碟的内容。
78. 作为收藏者，我希望 Virtual track 和普通 Track 在详情里有可区分的标记，并能看到对应的整轨文件和 CUE，以便了解底层结构。
79. 作为收藏者，我希望看到每首 Track 的格式、采样率、位深和时长，以便核对版本。
80. 作为收藏者，我希望看到专辑在磁盘上的位置，并能在 Finder 或文件管理器中显示，以便需要时直接去 NAS 上处理。

### 编辑：合并、拆分与封面

81. 作为收藏者，我希望把被误分成多张的 Album 合并成一张（各自成为 Disc），以便纠正识别错误。
82. 作为收藏者，我希望把被误合并的 Album 拆成多张，以便纠正识别错误。
83. 作为收藏者，我希望合并和拆分的结果在重新扫描后仍然保留，以便不必重复操作。
84. 作为收藏者，我希望撤销合并或拆分，以便操作失误时可以回退。
85. 作为收藏者，我希望 Cover 自动识别：优先专辑目录里的 cover/folder/front/封面 图片，其次 Disc 目录和 Booklet 目录，再次目录里唯一的一张图，最后是内嵌封面，以便绝大多数专辑自动有封面。
86. 作为收藏者，我希望从专辑目录及其附件目录的图片、或内嵌封面中手动选择 Cover，以便自动选错时能纠正。
87. 作为收藏者，我希望把封面恢复为自动选择，以便回退。

### 待处理（Needs attention）

88. 作为收藏者，我希望有一个独立的"待处理"视图，集中列出所有需要我决定的问题，并显示数量，以便有计划地清理。
89. 作为收藏者，我希望每条待处理都写明原因和涉及的路径，以便不用猜就知道该怎么处理。
90. 作为收藏者，我希望在 NAS 上改名或移动过的专辑文件夹，在重扫后以"可能是改名/移动"列出旧路径 → 新路径，以便我的编辑不会悄悄丢失。
91. 作为收藏者，我希望确认一条改名候选后，我的字段编辑、User tag 和 Manual collection 成员资格一次性迁移到新路径，以便整理成果跟着专辑走。
92. 作为收藏者，我希望否决一条错误的改名候选，以便它不再出现。
93. 作为收藏者，我希望在我做出决定前又改名一次时，候选自动更新为"最初路径 → 最新路径"；改回原名时候选自动消失，以便列表始终反映真实情况。

## 实现决策（Implementation Decisions）

### 产品决策（Q1–Q22）

- **Q1 对 NAS 只读**（ADR 0001）：第一期只读取 Library root，所有整理结果写入 Voon 自己的数据库。改名、移动、写标签、切分 CUE、清理杂项等写操作留到以后，届时每项都必须"先预览 → 确认 → 记录撤销日志"，并且默认关闭。
- **Q2 字段优先级**：UserEdit > Tag > Cue > FolderName。每个专辑级字段保存所有候选值及其 Field source，读取时取最强的来源。在线查询（MusicBrainz、Discogs）放到第二期。
- **Q3 识别规则**：
  - 含音频的文件夹是 Album；碟号命名的子文件夹并入上级成为 Disc。
  - Booklet、Scans、Artwork 等附件目录不参与结构识别，只用来找封面。
  - 只含 Album 的文件夹是 Collection，可以嵌套。
- **Q4 Virtual track**（ADR 0002）：
  - CUE sheet 加 Whole-disc image 生成 Virtual track，绝不切分文件。
  - "每首一个文件"的 CUE 只提供曲名。
  - CUE 按 BOM、严格 UTF-8、UTF-16 启发式、legacy CJK 检测（GBK / Shift-JIS 等）的顺序解码。
- **Q5 古典乐**：作曲家、演奏者、指挥、乐团作为专辑级字段，支持按作曲家浏览。"作品"层级的归并放到第二期。
- **Q6 分类**：
  - 自动 Facet：格式、采样率/位深、DSD/PCM、语种、年代；流派只读 Metadata tag。
  - 另外还有 User tag 和 Manual collection。
  - 智能合集以后再做。
- **Q7 不做播放**：只提供"用默认播放器打开"。
- **Q8 非音乐文件一律忽略**：唯一的例外是封面图片，包括目录中的图片和内嵌封面。
- **Q9 本地索引**：
  - 本机 SQLite，NAS 离线时可以浏览。
  - 增量重扫：用文件大小加修改时间判断是否需要重读标签。
  - 支持多个 Library root。
- **Q10 仓库**：项目名 Voon，仓库 chiyiangel/voon，Rust 加 GPUI，不与其他项目共享代码。
- **Q11 界面布局**：三栏（导航 / 专辑列表 / 详情），以 HTML 高保真原型为准：https://voon-design-canvas.vercel.app（对应 PR #1）。2026-11-11 Mobert 已在实现会话中明确确认「按现有原型开始实现」；原型中的示意数据与超出本规格的功能不进入第一期。
- **Q12 首次扫描**：在后台进行，逐张呈现 Album，可以取消；取消时保留已经找到的部分。
- **Q13 待处理视图**：列出每类问题及原因（问题类型见下文）。
- **Q14 编辑范围**：专辑级字段、合并或拆分 Album、选择封面。曲目级编辑不在第一期。
- **Q15 语言**：界面只有中文；代码和文档使用 GLOSSARY 中的英文术语。
- **平台**（ADR 0003）：
  - 支持 macOS 和 Linux（X11、Wayland），共用同一套代码；平台差异只放在应用层边缘，目前只有默认 Library root 不同。
  - Linux 在开发机上实际构建、lint、测试并启动验证；macOS 由 Mobert 手工验证。
  - 暂不设托管 CI。
- **Q16 改名检测**（ADR 0004）：
  - 用户数据（字段编辑、User tag、Manual collection 成员资格）以 Album 路径为键。
  - 每张 Album 保存一个 Content signature：专辑内各音频文件的相对路径加大小，取哈希。
  - 重扫时，若一个旧路径消失、同时恰好出现一个签名相同的新路径，就记录一条 Rename candidate 并列入待处理。
  - 用户确认后，在一个事务内迁移全部用户数据；也可以否决。
  - 歧义匹配不提议；多次改名会串接成一条；过期的候选自动清除。
- **Q17 专辑套专辑**：两张都保留，外层专辑列入待处理。
- **Q18 根目录散音频**：按"专辑名 + 专辑艺术家"标签分组成 Album，这类 Album 使用不会与真实目录冲突的合成路径。没有专辑标签的文件逐个列入待处理。根目录下的碟号文件夹视为独立 Album。
- **Q19 DSD 标签**：DSF 读取文件头里的流属性，以及元数据偏移处的 ID3v2 标签。DFF 第一期不读标签和属性，留到第二期。
- **Q20 乐团**：第一期只能由用户编辑填写，第二期通过在线查询自动补全。
- **Q21 macOS 打包**：第一期末交付带图标的 .app，不签名、不公证（个人使用）。
- **Q22 许可证**：MIT。

### 模块与接口

**voon-core（无 GUI 依赖，可在 Linux 上构建和测试）对外提供一个门面，包括：**

- **扫描**
  - 对一个 Library root 执行只读扫描，返回 Album（含 Disc、Track、Cover、带来源的元数据、Content signature）、Collection、扫描问题，以及每个音频文件的大小和修改时间。
  - 扫描接受一个进度回调和一个取消标志：每完成一张 Album 就通知一次，取消后返回已找到的部分，并标明已取消。
  - 标签读取通过可替换的"标签读取器"注入。默认读磁盘；带缓存的读取器先查索引，大小和修改时间未变就不再读文件；测试中可以用假的读取器。
- **索引**
  - 打开或迁移数据库（按版本号顺序执行迁移）。
  - 增删和列出 Library root。
  - 以 Library root 为单位整体替换扫描结果。
  - 查询 Album 列表（已叠加用户编辑）、Collection、待处理问题。
- **编辑**
  - 设置或清除某个专辑级字段的用户值。
  - 增删 User tag。
  - 创建 Manual collection、增删成员、调整顺序。
  - 待新增：合并或拆分 Album、手动选择 Cover。两者都以用户数据的形式保存，重扫后保留，并且可以撤销。
- **改名候选**：列出、确认（事务性迁移，返回各类迁移数量）、否决。
- **Facet**：由 Album 推导格式集合、DSD/PCM、分辨率等级、最高采样率和位深、年代、语种。
- **待新增**：Library root 级的用户忽略规则，作为内置杂项过滤之外的补充。

**voon-app（GPUI）分两层：**

- **状态层（view-model）**
  - 持有当前 Library root 列表、扫描状态（空闲 / 扫描中及进度 / 已取消 / 完成 / 未挂载）、导航选中项（全部 / Collection / 作曲家 / Facet / User tag / Manual collection / 待处理）、筛选与排序、搜索词、选中的 Album，以及编辑中的草稿。
  - 所有交互都表现为对状态层的操作。状态层调用 voon-core，并在后台线程上运行扫描。
- **视图层**
  - 按原型渲染三栏界面，只读取状态层的数据、把用户操作转发给状态层，本身不包含业务逻辑。

### 数据结构（概念层面）

- **扫描结果**（每次重扫按 Library root 整体重建）：Library root、Collection（含父级）、Album（路径、目录名、所属 Collection、Cover、Content signature）、各字段按来源存放的候选值、Disc、Track（编号、曲名/艺术家及其来源、格式、文件或 CUE 区间、音频属性）、扫描问题。
- **文件缓存**：按路径保存大小、修改时间和标签内容，用于增量重扫。
- **用户数据**（以 Album 路径为键，跨重扫保留）：字段编辑、User tag、Manual collection 及其顺序、Rename candidate；以后还会加入合并/拆分记录和封面选择。

### 待处理问题类型

- 可能是改名/移动（旧路径 → 新路径）
- 根目录散音频缺少专辑标签（逐个文件）
- 专辑里套着专辑（外层 → 内层）
- CUE 指向的文件不存在（哪个 CUE、找不到哪个文件）
- CUE 没有曲目
- 标题仅来自目录名
- 目录无法读取（附错误信息）

## 测试决策（Testing Decisions）

Mobert 只批准了以下两个测试接缝，不新增其他接缝，也不为内部模块补写单元测试（已有的保留）：

1. **voon-core 公共接口**：用形状与真实 NAS 一致的假音乐库驱动。假库包括 GBK CUE 加整轨、Philips Duo 的 CD1/CD2/Booklet、演奏家文件夹、DSD、双 CUE、分轨 CUE、损坏的 CUE、杂项文件、根目录散音频、改名和移动等场景。音频可以是占位文件，配合假的标签读取器；需要真实格式时再合成最小文件，例如合成 DSF。已有的集成测试（扫描、索引往返、增量缓存、改名候选、散音频、嵌套专辑）就是范例。
2. **voon-app 状态层**：用 GPUI 的测试上下文驱动，断言"交互 → 状态"。覆盖添加 Library root、开始和取消扫描、逐张出现 Album、筛选、编辑后来源变为用户编辑、确认改名候选后待处理数量减少等。不做像素或截图测试。视觉正确性以已评审的原型为准，加上人工检查。

**好测试的标准**：只断言外部可观察的行为，即公共接口的返回值、索引中查询得到的结果、状态层暴露的状态。不断言内部函数、SQL 结构或渲染细节。重构内部实现不应导致测试失败。

## 不在范围内（Out of Scope）

- 音乐播放（包括 DSD 和 APE 解码与输出）
- 对 NAS 的任何写操作：改名、移动、写标签、切分 CUE、清理杂项
- 在线元数据查询（MusicBrainz、Discogs），以及由此自动补全乐团
- 古典乐"作品"层级的归并
- 智能合集
- DFF 的标签和音频属性
- 曲目级字段编辑
- macOS 代码签名和公证
- Windows
- 托管 CI
- 英文或其他语言界面
- 跨 Library root 的改名检测，以及基于音频内容哈希的匹配

## 补充说明（Further Notes）

- **已知限制**
  - 改名检测只在同一个 Library root 内生效，并且要求音频文件本身未变：重新编码或改标签导致文件大小变化时无法配对；内容完全相同的拷贝不会自动配对。
  - 因为 GPUI 间接依赖的 xattr 0.2 在新版 libc 上无法在 Linux 编译，libc 被限制在 0.2.190 以下，不要随意解除。
  - macOS 构建尚未实际验证，首次编译需要完整的 Xcode 来编译 Metal 着色器。
  - DSF 标签读取只在合成文件上测试过，尚未用真实抓轨验证。
  - Wayland 只编译过，没有实际运行过；Linux 仅在 X11 上运行验证过。
  - 非常短的 legacy 编码 CUE 仍可能被误判编码。
- **界面工作的前提**：2026-11-11 Mobert 已确认按 HTML 原型（PR #1）开始实现，界面工单的外部门槛已满足。
