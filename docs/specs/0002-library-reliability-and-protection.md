# 资料库扫描可靠性与离线浏览

## Problem Statement

我的音乐收藏位于 NAS，包含整轨加 CUE、多碟套装、不同编码的标签和封面。我需要在 Voon 中放心地浏览、校正和分类这些收藏，同时保持音乐库文件只读，NAS 未连接时也能继续查看已经整理过的资料。

当前实现存在几处会降低可信度的行为：部分目录暂时不可读时，旧专辑可能从索引消失；一次标签读取失败可能被缓存成永久缺失，文件没变化就不再重试；字段只留下优先级胜出的值，无法比较其他来源；CUE 明确给出的曲目时长可能没有显示，曲目演奏者也未呈现；封面只有内存缓存，退出应用后再离线启动无法保证显示。

我希望先修正这些可靠性问题，再扩展智能合集、相关版本和古典关系。本轮从新建资料库重新扫描开始，不要求旧库迁移，也不实现备份和恢复功能。

## Solution

Voon 以 Album 的完整结构观察作为发布和确认缺失的依据。局部目录读取失败时保留上次完整的 Album，并显示本次读取不完整及原因；其他完整读取的 Album 正常更新。标签读取失败单独处理，保留上次成功资料，下次重扫可以恢复读取，并提供重试失败项和强制重读入口。

Voon 保存现有字段的全部可用本地候选及 Field source，在详情中提供比较，继续采用 UserEdit > Tag > Cue > FolderName 的优先级。人工编辑经重扫保留，恢复自动值时仍可查看其他候选。CUE 已知边界直接决定 Virtual track 时长，曲目级演奏者显示在详情中。

全部已入库 Album 的当前 Cover 在后台生成本地持久缩略图，包括用户手动选择的图片。扫描进度与封面缓存进度分别呈现；封面已就绪后，即使退出应用、断开 NAS 再启动，网格与详情仍能显示。暂时失败或尚未缓存的封面明确标注状态，可以在来源可用时重试。

已有资料库在发生写入前进行身份和结构版本检查；更高或无法识别的版本不会被误写。所有扫描、编辑和封面缓存保持对 Library root 只读。界面继续使用中文，保留现有 macOS 与 Linux 支持。

## User Stories

### 新建索引与日常使用

1. 作为收藏者，我希望从新建资料库重新扫描开始使用本轮功能，以便不必等待旧库资料转换。
2. 作为收藏者，我希望新建索引时保留已有旧库文件，以便新一轮扫描不会覆盖原来的本地资料。
3. 作为收藏者，我希望添加多个 Library root 并分别扫描，以便统一管理 NAS 和本机收藏。
4. 作为收藏者，我希望扫描和封面处理在后台执行，以便整理期间界面仍然可以操作。
5. 作为收藏者，我希望取消首次扫描后保留已经完整发现的 Album，以便下次继续使用已完成的成果。
6. 作为收藏者，我希望所有整理写入本机，以便音乐文件、CUE 和原始图片保持不变。

### 扫描完整性与索引保留

7. 作为收藏者，我希望某张 Album 暂时无法读取时保留上次完整资料，以便一次网络故障不会让它从收藏中消失。
8. 作为收藏者，我希望其他正常 Album 的新增和移除照常更新，以便单个故障不会阻止整个资料库收敛。
9. 作为收藏者，我希望多碟 Album 中一张 Disc 不可读时仍保留原有全部 Disc 和 Track，以便专辑不会被误显示成残缺版本。
10. 作为收藏者，我希望首次发现但未完整读取的位置显示在 Needs attention 中，以便知道哪里失败而不会把部分曲目误认为整张专辑。
11. 作为收藏者，我希望看到“本次读取不完整”、相关位置和原因，以便区分旧资料与本次已经成功确认的资料。
12. 作为收藏者，我希望目录失败时仍能浏览、搜索和查看已知资料，以便 NAS 不稳定时仍能使用本地索引。
13. 作为收藏者，我希望重试成功后更新资料并解除对应失败状态，以便知道问题已经解决。
14. 作为收藏者，我希望只有完整成功观察到内容缺失后才从正常列表移除它，以便真正删除与暂时不可读得到不同处理。
15. 作为收藏者，我希望索引中的内容移除后仍保留路径关联的人工整理，以便重新出现时可以继续使用。
16. 作为收藏者，我希望曾有内容的 Library root 本次变空时先核对并确认，以便空挂载点不会被当成音乐全部删除。
17. 作为收藏者，我希望整个 NAS 未挂载或扫描中断连时保留旧索引，以便离线状态不会清空收藏。
18. 作为收藏者，我希望取消重扫后未访问的 Album 保持原样，以便取消动作不会被解释为内容消失。
19. 作为收藏者，我希望不完整扫描不产生错误的 Rename candidate，以便不会因读取失败迁移人工整理。
20. 作为收藏者，我希望合并拆分结果和撤销能力经失败扫描后保持可用，以便结构纠错不会被不完整结果破坏。
21. 作为收藏者，我希望列表、Collection 导航和计数反映同一份已接受的资料，以便不会出现详情还在而侧栏已经消失的矛盾。

### 标签失败与恢复读取

22. 作为收藏者，我希望一次标签读取失败时保留上次成功的元数据，以便暂时错误不会把资料抹为空白。
23. 作为收藏者，我希望文件大小和修改时间未变时仍能重试失败读取，以便网络恢复后无需修改音乐文件。
24. 作为收藏者，我希望读取错误显示路径、阶段和可理解的原因，以便判断应重新连接还是检查源文件。
25. 作为收藏者，我希望“成功读取但没有标签”区别于“读取失败”，以便知道缺失资料是否真实。
26. 作为收藏者，我希望未支持的格式明确标为未支持，以便不会把它误认为损坏文件。
27. 作为收藏者，我希望解析失败有独立提示，以便无法解析的资料不会被静默归为无标签。
28. 作为收藏者，我希望能重试失败项，以便恢复读取时不必反复处理整个资料库。
29. 作为收藏者，我希望能对选中 Album 强制重读标签，以便主动绕过缓存核对源文件。
30. 作为收藏者，我希望普通重扫继续复用成功且未变化的标签，以便日常增量扫描保持高效。
31. 作为收藏者，我希望取消重试或强制重读后仍保留已接受的完整资料，以便中途停止不会造成数据缩减。
32. 作为收藏者，我希望失败重试按相关 Library root 和 Album 限定影响范围，以便另一处收藏不受干扰。

## Implementation Decisions

### 范围与既有边界

- 本轮实现 F1 扫描完整性、F2 标签失败恢复、F3 本地字段候选、F4 CUE 呈现、F5 持久缩略图，以及通用资料库版本检查。
- 以新建库重新扫描为使用和验收起点，保留现有旧库文件。无需新增旧库迁移、历史候选恢复、旧库专用补齐任务或人工整理导入流程；既有迁移代码和历史测试不因本规格而删除。
- 沿用 Album、Disc、Track、Virtual track、Collection、Manual collection、Cover、Field source 和 Rename candidate 的既有含义。不同发行保持独立 Album，Version group 和 Copy 的管理功能不在本轮实现。
- 继续遵守音乐库只读、CUE 虚拟曲目、macOS 与 Linux 同一代码库，以及同根目录改名候选人工确认的 ADR。备份相关 ADR 的实施状态保持延期。
- voon-core 负责领域数据、扫描、候选选择与本地索引；voon-app 的状态层编排后台任务和交互，视图渲染已公开状态。平台目录和系统播放器调用保持在现有平台边界。

### 扫描完整性与发布契约

- 扫描结果表达成功观察的范围、未完成或失败的范围、问题原因及取消状态，不能再仅凭“未取消且返回了一些专辑”把整个 Library root 当成完整快照。
- Album 的结构完整性与标签读取状态、封面缓存状态分开表达。相关目录和曲目结构未完整读取时保留上次完整 Album；单个标签读取失败不等于文件或 Track 不存在，封面失败也不阻止结构完整的 Album 入库。
- 已有 Album 的任一相关 Disc 或目录失败时，不发布缩水的结构，不改变原有曲目集合。其他独立、完整观察的 Album 可正常发布；失败状态与保留的旧资料同时可查。
- 首次发现但没有上次完整结果的位置，通过现有 Needs attention 机制显示路径、阶段、原因和重试入口，不把已读到的部分曲目作为完整 Album 正常发布。
- 只有成功完整观察的范围可以确认内容缺失。完整读取后确认移除的项目从正常索引展示中消失，路径关联的人工编辑、User tag、Manual collection 成员和 Cover 选择按现有保留语义处理。
- 根目录不可用、设备变化和取消都不能清除未访问内容；既有非空根目录本次为空时继续使用人工确认流程。
- 不完整范围不能用于推断 Rename candidate。扫描基线和结构操作的原始观察只接受相应完整结果，不能因部分扫描污染下一次改名判断或撤销。
- 通过 Index 的公共提交与查询接口落实这些规则，保证 Album、Disc、Track、候选、Collection 导航和计数一致；新扫描结果不能覆盖扫描期间已提交的人工编辑。
- 保留现有后台进度与逐 Album 呈现能力，仅让完整发现的 Album 进入该流程。取消后保存已完成部分，重启可以浏览；本轮不要求逐目录精确断点续传。
- 本轮沿用既有 CUE 识别与问题检测，不扩展成损坏 CUE 自动修复器。凡现有失败已经导致曲目结构无法完整判断，不能将不完整结果发布成已确认的完整结构。

### 标签结果与增量缓存

- 标签读取结果区分成功且有数据、成功但无标签、格式尚未支持、暂时 I/O 失败和解析失败。扩展现有标签读取与缓存契约，避免将不同结果全部折叠成空值。
- 成功数据与失败记录分开保留。暂时或解析失败不能覆盖上次成功值，也不能因相同文件大小和修改时间而长期阻止恢复读取。
- 普通重扫对上次失败来源进行重试，对成功且未变化的文件继续复用缓存。已知未支持格式不进入无休止自动重试。
- 提供重试失败项，以及对选中 Album 强制重读标签的操作。强制重读绕过相关标签缓存，不改变其他 Album 的成功缓存，也不改写源文件。
- 每次用户触发的重试只执行有限的一轮工作，使用现有后台扫描编排和取消机制；本轮不新增持续监视、定时扫描或自动循环重试服务。
- 上次成功资料被保留时标明尚未重新确认；没有成功历史的来源如实呈现未知与错误。成功确认无标签是有效观察，不与暂时失败混淆。

### 字段候选与显示值

- 扩展现有 AlbumMetadata、扫描结果和 Index 公共读模型，分开表达候选集合、当前自动值、人工覆盖及来源读取状态，不要求界面自行组合低层存储记录。
- 覆盖当前十个专辑字段：标题、专辑艺术家、年份、流派、唱片编号、版本、作曲家、演奏者、指挥、乐团。保留现有来源支持范围；流派继续只取 Metadata tag，乐团没有自动来源时仍可由用户编辑，不新增标签映射或在线推断。
- 候选至少保留字段、解析出的值、Field source、具体源文件或目录、适用曲目范围和真实观察时间。同来源不同文件的值不能在保存之前被多数票归并丢弃；界面可以折叠相同值，但仍须能查到全部来源。
- 当前值继续采用 UserEdit > Tag > Cue > FolderName。自动来源内部维持现有确定性多数值和先到值规则；保留不同候选不意味着改变默认选择策略。
- 成功且未变化的缓存命中沿用原候选及观察时间，不把本次缓存命中或源文件修改时间冒充新读取时间。成功重读后更新对应来源，失败则保留上次成功候选并标记读取状态。
- 只保留当前来源观察及恢复读取所需的上次成功结果，不引入无限历史版本、采纳审计系统或元数据备份。
- 详情提供只读候选比较，显示采用值、自动值、人工值和出处。保留现有编辑器及恢复自动值操作，不新增逐字段来源偏好或批量冲突处理。
- 沿用现有空白输入表示清除人工覆盖、恢复自动值的语义，使用准确文案；不增加人工指定为空的独立值层。
- 候选差异是可查看的来源信息，不据此自动创建人物、作品或新的年份分类，也不把不同曲目的作曲家一律认定为错误。

### CUE 时长与曲目演奏者

- Virtual track 有合法起止边界时，按每秒 75 帧计算区间时长；该计算独立于音频标签或属性读取是否成功。
- 起点为 0、终点为 13500 帧的曲目，其时长为 180000 ms。末轨有已知整轨总长时显示剩余时长；无终点且总长未知时保持未知。
- 详情逐轨展示已解析的演奏者。数据库往返、重启和结构纠错保持曲目来源、时长和演奏者信息。
- 保留 Virtual track 的映像与 CUE 边界，不切分或转码。默认播放器入口如实说明打开整个映像，不承诺按虚拟曲目起点定位。
- 不以本修正为由引入 DFF 标签或音频属性解析；DFF 仍能利用 CUE 本身已经提供的明确边界。

### 本地持久缩略图

- 后台为全部已入库 Album 的当前有效 Cover 准备持久缩略图，不以是否已经滚动到视口为条件；自动封面和手选封面使用同一套就绪与失效规则。
- 缩略图写入平台标准应用数据位置，独立于 Library root。覆盖外置图片、内嵌图片及已选内嵌图片索引，保留当前 Cover 选择与资产的关联。
- 内存缓存继续有界；内存淘汰不能删除当前 Album 已承诺可离线使用的持久缩略图。不新增磁盘缓存配额或通用图片收藏管理功能。
- 缓存身份结合当前封面选择和来源变化判定，来源图片或音频发生变化时重新读取。异步任务携带有效的选择和任务身份，过期完成结果不能覆盖较新选择。
- 本地资产完整写入且可读取后才标记已就绪。单张图片读取、解码、写入或缓存损坏只影响相关 Cover，不清除 Album、用户选择或其他缓存。
- 未缓存、进行中、已就绪、失败和没有 Cover 分别表达；缓存统计独立于扫描状态。缓存任务结束但存在失败时，不将全部封面标记为已就绪。
- 来源不可用时保留已有有效的当前缩略图；当前选择尚无有效缓存时明确显示占位与状态，不把另一张旧封面冒充当前选择。
- 来源恢复后提供失败封面重试，复用现有后台加载编排。读取、解码与写入有界并发，不阻塞 UI 渲染。
- 只承诺当前封面的缩略图，不复制整本小册子、原尺寸图片或全部历史封面，也不创建 Library backup。

### 资料库身份与版本保护

- 已有库在执行写入性初始化、迁移或业务写入之前完成身份与结构版本检查；拒绝更高或无法识别的库，不以清空、自动降级或重建替代检查。
- 拒绝过程中不改写被检测的已有库及相关文件，向用户说明不兼容原因及新建库重新扫描的选择。
- 不存在目标文件时可以正常创建本轮新库；不能将任意已有数据库因缺少熟悉表而当成空库初始化。
- 扫描完整性、来源实例与读取状态、字段候选及缩略图关联所需的本地结构在新库中建立。既有历史迁移支持不扩展为本轮承诺，未来新增兼容路径必须单独验证。
- 不引入备份格式识别、备份迁移、恢复前保护份或在副本中升级的恢复系统。ADR 中实施延期的备份要求不构成本轮依赖。

### 界面与状态一致性

- 复用现有设置、扫描横幅、Needs attention、Album 详情和编辑入口；不要求新的整套视觉原型，也不增加与本轮无关的导航模块。
- 问题显示用户可理解的中文阶段、路径和原因，提供与该问题对应的重试操作，不把内部函数名、SQL 或堆栈作为主交互文案。
- 切换选择、移除 Library root、取消任务或执行新的扫描后，失效后台消息不能重新发布旧数据或覆盖较新的状态。
- 普通扫描、标签重读、候选比较、人工编辑和封面缓存各自保留真实状态；单项失败不能被包装成整个资料库已经完整成功。

## Testing Decisions

### 测试接缝

沿用第一期已批准的两个接缝，不增加第三个测试接缝：

1. **voon-core 公共接口**：用真实形状的临时音乐库驱动公开扫描、标签读取契约、Index 提交与查询。通过查询结果及关闭重开后的行为验证完整性、候选和版本保护；需要控制失败时复用现有标签读取器和公开扫描结果。
2. **voon-app 应用状态层**：用 GPUI 测试上下文驱动用户操作及公开状态，复用既有 Scanner 和 CoverLoader 边界。持久封面验证通过应用状态与真实加载、临时本地存储的整合场景完成，不能仅用假加载器返回成功来证明持久性。

测试只断言外部行为：哪些 Album 和 Track 可查询、人工数据是否保留、候选及来源是否可读、重试是否真实发生、状态是否解除，以及重启离线后能否加载图片。不为内部解析函数、私有 SQL、缓存字典、枚举布局或组件几何新增独立单元测试；已有测试保留。

### 核心与状态层验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| A 不可读，B 正常变化 | A 保留上次完整资料并有失败状态；B 正常新增和移除；重开索引后相同。 |
| 多碟专辑一碟失败 | 原 Disc 与 Track 数量不缩水，成功重试后整体更新。 |
| 首次发现就不完整 | Needs attention 有路径及原因，不把部分曲目当作完整 Album。 |
| 根离线、扫描中断连、取消 | 未访问资料与人工整理保留，不误推断 Rename candidate。 |
| 既有非空根本次为空 | 未确认前保留索引和基线，明确确认后才接受空结果。 |
| 临时标签失败后恢复，stamp 不变 | 下一次普通重扫实际调用读取器，补齐资料并解除错误；缓存不永久阻止重试。 |
| 成功无标签、未支持、解析失败 | 结果与提示可区分，失败不抹去上次成功候选，未支持不无限自动重试。 |
| 普通增量与选中 Album 强制重读 | 未变的成功标签读取数为零；强制重读仅绕过相关缓存。 |
| 多文件、多来源候选及人工覆盖 | 所有来源可查，默认优先级不变，重扫及重开保留人工值，恢复自动值不丢候选。 |
| 标签读取失败的 DFF 加双轨 CUE | 首轨 0 到 13500 帧仍为 180000 ms；末轨无总长则未知；各轨演奏者保留。 |
| 合并拆分与局部失败交错 | 原结构计划、来源和撤销仍可用，不重复曲目，不丢组织关系。 |
| 超过内存缓存容量的已知封面 | 仅有限项驻留内存不影响持久资产，重建应用状态后仍能离线读取。 |
| 全库封面缓存后冷启动 | 未逐张浏览的 Album 也有图；退出实际进程、断 NAS、再次启动后网格和详情一致。 |
| 快速更换封面及旧任务迟到 | 最终图片对应最新选择，旧任务不能回写旧封面。 |
| 单张缓存损坏或来源不可读 | 相关项可理解地失败或使用有效当前缓存，其余资料正常；来源恢复后可重试。 |
| 更高或无法识别的资料库 | 在写入前拒绝，源文件和已有相关文件保持原样；新库正常创建、重开与扫描。 |
| 源库只读 | 所有操作前后，音乐库文件集合、内容与修改时间保持不变；本地产物不落入 Library root。 |

目录权限失败应在可真实制造读取拒绝的临时环境中验证。仅用受控 Scanner 返回失败结果能证明应用发布行为，不能据此声称真实目录错误检测已经受测。标签失败接缝注入和占位 DFF 也不能替代真实 SMB 或真实格式读取验收。

### 现有测试范例

- 核心扫描和索引往返测试已经覆盖 Album、Disc、Collection、CUE 和用户编辑，可扩展相同的公开调用方式。
- Library root 测试已有取消后重开、部分重扫不丢未访问专辑、同秒 stamp 变化以及移除根后保留人工数据的范例。
- 专辑详情测试已有 CUE 曲目、属性和 Field source 往返；专辑编辑测试已有保存、恢复自动值及表单事务行为。
- 结构测试已有重扫重放、撤销、虚拟曲目拆分再合并及改名确认后的来源更新，作为防回归依据。
- GPUI 重扫测试已有真实 worker 的读取数验证、ControlledScanner、离线保留和空挂载点确认；封面选择测试已有草稿、应用、取消和恢复自动封面的状态操作。
- 持久缩略图需要增加真实本地资产的重开与离线读取场景，不能仅延长内存对象寿命来通过验收。

### 真实样本、平台与完成条件

- 使用临时故障库和约 20 张用户认可的真实专辑，覆盖多编码 CUE、整轨、多碟、DSD、不同标签来源、外置和内嵌封面。
- 自动测试通过后进行实际窗口验收，重点检查不完整 Album 提示、候选比较、逐轨演奏者，以及退出进程后的离线封面。GUI 渲染结论不能只靠状态层测试代替。
- 继续执行工作区测试、严格 Clippy、格式与差异检查；保持 macOS 与 Linux 的构建和既有平台验收要求。不可用的平台环境必须如实记录未验证，不能以 macOS 结果代替 Linux 或 Wayland。
- 新失败场景、恢复后的结果以及源库只读检查都要有可复核证据。既有 123 项通过只是此前基线，不是本规格已经完成的证明。
- 每项交付必须覆盖完整链路：后台观察与分类、持久化、公开查询、应用状态和实际可见行为；不能把只加数据字段或只加界面按钮视为修正完成。

## Out of Scope

- Library backup、自动或手动备份、备份轮换与清理、备份格式兼容、恢复入口、恢复前保护份、损坏库隔离及升级前自动备份。
- 本轮前旧库的升级承诺、来源补齐、历史候选重建和人工整理迁移；现有旧库文件保留。
- 实时目录监视、周期扫描、后台常驻服务、自动无限重试，以及精确的逐目录断点续传。
- 在线元数据查询或自动采纳、批量冲突审阅、逐字段来源偏好和无限候选历史。
- Version group 或 Copy 管理、稳定专辑身份重构、跨 Library root 自动重新关联、音频内容指纹。
- 人物和乐团实体、别名归一、Work、Recording、作品乐章归并、新的年份语义字段或新的标签映射。
- 智能合集、保存筛选、扩大搜索范围和新的全局组织功能。
- 音乐播放、CUE 曲目定位播放、转码、整轨切分、DFF 标签或音频属性解析。
- 对音乐库的改名、移动、写标签、删除、清理或创建 sidecar 文件。
- 损坏 CUE 的自动修复、新的通用 CUE 编辑器。
- 小册子全文缓存、原尺寸图片收藏、历史封面管理和通用磁盘缓存配额。
- 人工指定空值的新语义、曲目级元数据编辑、全套界面重设计。
- Windows、新语言界面、代码签名或公证，以及新增托管 CI。
