# 菜单栏与独立设置窗口

> 后续入口调整见[侧栏分类设置窗口](../design/2026-11-12-settings-sidebar.md)：资料库菜单和内容维护入口统一跳转设置分类。原窗口生命周期和数据保护要求继续适用。

## Problem Statement

我希望音乐资料库浏览界面专注于查找、查看和整理 Album。当前“设置 · 音乐库”常驻主浏览区，打开设置后还会替换中央内容；路径、目录管理和忽略规则与日常扫描操作混在一起，打断浏览，也不符合我在 macOS 顶部菜单中寻找应用设置的习惯。

将设置移到独立窗口还必须保护现有工作：当前关闭任意窗口都会退出应用；新建索引会替换当前资料库状态，但尚未检查专辑和封面的未提交编辑。我需要打开和关闭设置时保留浏览位置与编辑草稿，并清楚知道哪些修改立即保存、哪些下次扫描生效、哪些操作在扫描时不可执行。

## Solution

macOS 使用屏幕顶部原生应用菜单“Voon → 设置…”；Linux 在应用窗口顶部提供可见菜单栏。菜单和快捷键打开同一个独立、非模态设置窗口，重复打开时聚焦已有窗口。设置展示本地索引路径，并提供音乐目录（Library root）增删、忽略规则和已有的新建索引操作。主浏览区移除常驻设置行，中央区域继续用于浏览。

设置窗口与主窗口共享当前资料库。仅打开、聚焦或关闭设置不改变浏览位置、选择和未提交编辑，也不停止扫描。关闭主窗口沿用当前退出应用的行为；关闭当前窗口和退出应用有各自的菜单动作及平台快捷键。

按 Library root 选择的增量重扫迁入“资料库 → 重新扫描 → 音乐目录”。失败重试、选中 Album 强读标签保留在 Needs attention 与专辑上下文；扫描进度和取消继续在主窗口显示。首次使用页面提供直达设置的添加目录引导；索引不可用页面继续说明原因并保留新建索引入口。

配置即时保存。添加目录后启动扫描；忽略规则明确标注“下次扫描生效”。扫描期间仍能打开设置、查看配置和保存忽略规则，但不能增删音乐目录或新建索引。有未提交的专辑或封面编辑时，需先保存或取消编辑才能新建索引。设置操作的失败原因和受限原因在设置窗口内可见。

## User Stories

### 入口与设置范围

1. 作为 macOS 用户，我希望在屏幕顶部的“Voon → 设置…”找到应用设置，以便使用熟悉的系统入口。
2. 作为 Linux 用户，我希望在应用窗口顶部看见菜单栏和设置入口，以便无需依赖不可见的原生菜单配置。
3. 作为收藏者，我希望主浏览区不再常驻设置行，以便更多空间用于查看 Album。
4. 作为收藏者，我希望打开设置后中央浏览内容继续保留，以便无需重新寻找刚才的浏览位置。
5. 作为收藏者，我希望在设置中查看本地索引路径，以便知道资料保存在本机何处。
6. 作为收藏者，我希望在设置中添加和移除 Library root，以便集中管理资料库来源。
7. 作为收藏者，我希望在设置中管理忽略规则，以便控制后续扫描范围。
8. 作为收藏者，我希望在设置中找到已有的新建索引操作，以便在需要时保留原库并重新开始扫描。
9. 作为收藏者，我希望 User tag、Manual collection、专辑编辑、封面选择、合并拆分和 Field source 比较留在内容上下文，以便整理音乐时不必进入应用设置。

### 多窗口与快捷键

10. 作为收藏者，我希望设置在独立窗口中展示，以便配置路径和规则时仍能看见主资料库。
11. 作为收藏者，我希望重复打开设置时聚焦已有窗口，以便不会出现多份设置窗口。
12. 作为收藏者，我希望设置窗口打开时主窗口仍可操作，以便可以继续浏览、搜索和整理。
13. 作为收藏者，我希望仅打开或关闭设置时保留浏览位置、筛选、选择和编辑草稿，以便配置入口不会打断当前工作。
14. 作为收藏者，我希望关闭设置后应用继续运行，以便不会因为关闭辅助窗口而退出。
15. 作为收藏者，我希望关闭设置不会停止后台扫描，以便扫描任务不依赖设置窗口的寿命。
16. 作为收藏者，我希望关闭设置后仍可再次打开它，以便随时返回配置。
17. 作为收藏者，我希望关闭主窗口时沿用当前退出应用的行为，以便本轮调整不改变既有主窗口习惯。
18. 作为 macOS 用户，我希望通过 `⌘,` 打开设置、`⌘W` 关闭当前窗口、`⌘Q` 退出应用，以便使用熟悉的快捷键。
19. 作为 Linux 用户，我希望通过 `Ctrl+,` 打开设置、`Ctrl+W` 关闭当前窗口、`Ctrl+Q` 退出应用，以便获得相同的操作能力。
20. 作为收藏者，我希望菜单显示对应快捷键，以便逐步记住常用操作。
21. 作为收藏者，我希望主窗口和设置窗口显示同一份已保存配置，以便不会因为窗口不同而看到矛盾的资料库状态。

### 日常操作与不可用状态

22. 作为收藏者，我希望通过“资料库 → 重新扫描”明确选择一个 Library root，以便只更新指定来源。
23. 作为收藏者，我希望重新扫描沿用增量读取，以便入口迁移不会让未变化文件被无谓重读。
24. 作为收藏者，我希望目录增删后重扫菜单反映当前 Library root，以便不会选到已经移除的来源。
25. 作为收藏者，我希望失败重试仍能从 Needs attention 等相关入口执行，以便在看见问题时直接恢复。
26. 作为收藏者，我希望选中 Album 的强读标签操作继续位于专辑上下文，以便清楚知道它的作用范围。
27. 作为收藏者，我希望扫描进度、错误及取消仍在主窗口可见，以便关闭设置后也能管理任务。
28. 作为首次使用者，我希望从空资料库页面直接打开设置并添加目录，以便无需先了解菜单结构。
29. 作为索引打不开的用户，我希望故障页继续显示中文原因和新建索引入口，以便能够恢复使用。
30. 作为收藏者，我希望新建索引继续使用独立新文件并保留原库，以便调整界面不会削弱已有资料保护。

### 生效时机与工作保护

31. 作为收藏者，我希望配置修改即时保存，以便无需再寻找统一的保存设置按钮。
32. 作为收藏者，我希望添加 Library root 后随即启动扫描，以便保持当前添加目录的操作习惯。
33. 作为收藏者，我希望忽略规则明确说明“下次扫描生效”，以便不会误以为当前扫描已经采用新规则。
34. 作为收藏者，我希望扫描期间仍可查看设置和保存忽略规则，以便不必等待任务完成才能准备下一次扫描。
35. 作为收藏者，我希望扫描期间目录增删和新建索引被禁用并说明原因，以便避免来源或索引在任务中途切换。
36. 作为收藏者，我希望有未提交专辑编辑时阻止新建索引，以便先保存或取消当前编辑。
37. 作为收藏者，我希望有未提交封面选择时阻止新建索引，以便当前选择不会被静默丢弃。
38. 作为收藏者，我希望设置操作的失败原因直接显示在设置窗口，以便不必返回主窗口寻找错误。
39. 作为收藏者，我希望取消目录选择或被保护规则阻止时保留当前配置和资料库，以便尝试操作不会造成意外切换。
40. 作为收藏者，我希望移除 Library root 仍有确认，且保留已有人工整理、不删除音乐文件，以便入口调整不会改变既有数据保护语义。

## Implementation Decisions

### 设置与日常操作的职责

- 设置视图负责本地索引路径展示、Library root 列表及增删、忽略规则和已有的新建索引操作。索引路径展示不扩展为搬迁当前数据库的功能。
- 增量重扫从设置中移出，通过资料库菜单按当前 Library root 明确选择；不引入默认扫描全部目录的新命令。失败重试、强读标签、扫描进度、取消及现有扫描问题处理继续复用原有内容上下文和反馈区域。
- User tag、Manual collection、Album 编辑、Cover 选择、合并拆分和 Field source 比较保持原有职责，不归入应用设置。

### 平台菜单和共享命令

- macOS 使用 GPUI 提供的原生应用菜单，在“Voon”应用菜单中提供“设置…”及退出动作；资料库菜单提供按目录选择的重新扫描。这里的顶部菜单指屏幕顶部应用菜单。
- Linux 提供实际可见的窗口顶部菜单栏。当前锁定的 GPUI 在 Linux 上仅保存菜单配置，因此只调用菜单注册接口不算完成 Linux 入口。
- 菜单、快捷键和首次使用引导复用同一套应用操作；平台差异放在应用边界，资料库业务仍使用共享实现。
- 设置、关闭当前窗口、退出应用分别绑定 macOS 的 `⌘,`、`⌘W`、`⌘Q`，以及 Linux 的 `Ctrl+,`、`Ctrl+W`、`Ctrl+Q`，在菜单中展示对应键位。关闭当前窗口按获得焦点的窗口处理；退出动作在任一窗口中都退出应用。
- 重新扫描菜单基于当前资料库的 Library root 更新，不保留已移除来源的有效动作；无可用目录或操作受限时不发起扫描。

### 独立窗口与状态所有权

- 应用窗口协调负责打开、聚焦和关闭独立设置窗口，维护单实例语义；窗口存在时重复命令只聚焦，关闭后下次命令可重新创建。
- 设置与主窗口共享同一个应用状态实体和当前索引，不各自打开并维护一份可写资料库状态。配置变更和索引切换后，两个窗口与菜单都读取更新后的状态。
- 设置为非模态窗口。移除主窗口常驻设置行及中央区域的设置分支；仅打开、聚焦或关闭设置不重建浏览内容、不切换索引、不重置搜索、筛选、排序、选择、滚动位置或未提交编辑。
- 业务状态、扫描和后台任务不归设置窗口所有。关闭设置只结束该窗口；主窗口和后台任务继续运行。窗口协调的生命周期不随新建索引所替换的资料库状态一起丢失。
- 修正当前任意窗口关闭即退出的处理：仅关闭主窗口或明确执行退出动作时退出应用；关闭设置窗口及其关闭快捷键不触发应用退出。
- 主窗口现有的扫描消息处理和进度反馈继续工作，不因为打开或关闭设置而中断或重复启动任务。

### 配置生效与操作保护

- 延续即时保存模型，不新增全局“保存”或“应用”步骤。添加 Library root 成功后启动扫描；忽略规则保存后供下一次扫描使用，界面明确说明时机，不触发隐式重扫或改变当前扫描已经采用的规则。
- 扫描期间设置入口保持可用，可以查看配置和保存忽略规则；Library root 增删与新建索引不可执行，并显示可理解的中文原因。相关扫描操作包括普通扫描、失败重试和强读标签所复用的扫描任务。
- 保护判断位于应用操作边界，界面据此展示可用性；执行前再次核对状态。已打开的目录选择器、确认流程、旧菜单动作或快捷键不能绕过任务限制。
- 专辑或封面存在未提交编辑时，新建索引必须先被阻止并说明“先保存或取消编辑”。不自动保存、不静默取消，也不新增强制丢弃后继续的捷径。仅查看设置不清除草稿。
- 正常设置入口与索引故障页的新建索引操作遵循同一保护和创建语义。先成功创建独立索引再切换；保留原索引文件，失败或取消时不替换当前资料库。原有版本检查、索引位置限制和选择持久化继续有效。
- 移除 Library root 保留确认流程，继续隐藏其扫描结果并保留已有编辑、User tag 和 Manual collection，音乐文件保持不变。当前移除正在扫描目录会停止任务的行为，由已确认的“扫描期间禁止增删目录”规则替代。

### 引导与反馈

- 无 Library root 的首次使用页面保留直达引导，以“添加音乐目录…”等明确文案打开设置，由设置完成目录添加；不在中央浏览区保留完整配置面板或平行的添加配置流程。
- 索引不可用页面继续显示原因和“新建索引…”恢复入口，不能因正常浏览区移除设置行而失去恢复能力。
- 设置操作错误、受限原因与相关确认在设置窗口中可见；不要求用户切回主窗口扫描条才能了解设置操作失败原因。扫描进度和扫描问题仍由主窗口反馈，不混同为设置保存状态。
- 延续中文界面和既有视觉风格。此规格不要求新的整套视觉原型，也不增加无关导航。

### 数据与架构约束

- 本轮不需要新的数据库结构、迁移或扫描协议；复用已有索引、配置和扫描公共操作。应用窗口协调、菜单呈现与设置视图承担本轮调整，核心层保持无 GUI 和平台依赖。
- 遵守音乐库只读及 macOS/Linux 共用代码的既有 ADR；所有配置写入本机。新建索引也不得落入 Library root 或覆盖已有库。
- 入口迁移可逆，不为其新增 ADR；沿用领域词汇，不将通用菜单和窗口术语加入音乐领域词汇表。

## Testing Decisions

### 已确认测试接缝

用户已确认本轮沿用现有接缝，不新增第三个内部测试接口：

1. **主要入口：voon-app 应用状态层。** 用 GPUI 测试上下文驱动设置和资料库操作，观察公开状态、操作结果及实际索引查询。需要控制任务时复用既有 Scanner 和 CoverLoader 边界；主要新增自动化集中在这里。
2. **配套回归：voon-core 公共接口。** 复用临时索引、扫描结果、查询和关闭重开方式，检查配置持久化、移除目录后的人工数据保留、新建索引及源文件只读。优先复用已有回归，不为未修改的核心内部实现机械补测试。

好的测试验证用户可观察的结果：指定目录是否启动扫描、规则何时生效、受限操作是否被拒绝、草稿和当前索引是否保留、错误是否可读、保存后重开是否一致。不断言私有字段布局、窗口句柄存放方式、菜单构造数组、内部函数或 SQL；不新增像素和截图快照测试。

原生菜单、焦点、单实例窗口、关闭和快捷键的可用性通过实际窗口验收。状态层测试不能单独证明这些平台行为，也不因此新增针对 GPUI 内部或平台菜单的测试接缝。

### 自动化场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 添加 Library root | 保存来源并启动该目录扫描；已存在的目录限制和本地索引位置保护继续生效。 |
| 指定目录增量重扫 | 仅目标目录进入扫描；成功且未变化的标签继续复用缓存，不误扫其他来源。 |
| 扫描中尝试目录增删或新建索引 | 操作被拒绝并有可读原因；当前来源、索引和任务不被这些操作改变。 |
| 打开选择器或移除确认后，另一入口启动扫描 | 后续提交仍复查限制，不能使用此前可用的操作状态绕过保护。 |
| 扫描中保存忽略规则 | 配置保存成功；当前任务继续采用已取得的规则；下一次扫描使用新规则。 |
| 专辑编辑草稿存在时新建索引 | 操作被拒绝，当前索引和草稿保留；明确保存或取消编辑后才允许新建。 |
| 封面选择草稿存在时新建索引 | 操作被拒绝，当前索引和待提交选择保留；应用或取消后解除相关保护。 |
| 新建索引成功、失败或取消 | 成功才切换共享的资料库状态；失败或取消保留当前资料库；原索引及音乐文件不被覆盖。 |
| 设置操作失败 | 应用状态提供设置视图可用的中文原因；不以扫描完成状态掩盖设置失败。 |
| 配置保存并重开 | Library root、忽略规则和当前索引选择按既有语义持久保存。 |
| 移除目录再加回相同路径 | 确认前不移除，移除后音乐文件不变，已保存的人工编辑、User tag 和 Manual collection 仍可恢复使用。 |
| 索引不可用 | 中文原因继续可查，不能直接写入不可用索引，新建独立索引仍走已有保护。 |

### 现有范例

- 应用扫描与重扫测试已有 GPUI 测试上下文、受控 Scanner、后台消息推进、真实 worker 读取数及取消后的索引保留场景。
- 忽略规则测试已有“保存后不立即改列表、重扫后生效、移除规则后恢复”和离线移除规则场景。
- 专辑编辑与封面选择测试已有草稿、应用、取消和恢复自动值的完整操作流程，可扩展新建索引保护。
- 索引启动测试已有不可用索引的中文解释、保留旧文件、创建独立索引及重开场景。
- 核心 Library root 与人工整理测试已有移除目录后保留用户数据的往返检查。

### 实际窗口与完成门槛

| 验收项 | 必须观察到的结果 |
| --- | --- |
| macOS 菜单 | 屏幕顶部“Voon → 设置…”和资料库重扫菜单可见可用，菜单展示对应快捷键。 |
| Linux 菜单 | 窗口顶部实际显示菜单栏并可打开设置、选择目录重扫；不能以仅注册菜单配置代替可见入口。 |
| 设置单实例 | 从菜单、快捷键和首次使用引导打开时共用一个设置窗口；重复打开聚焦；关闭后能重新打开。 |
| 浏览与草稿保留 | 选中 Album、设置搜索和筛选、滚动列表并打开编辑或封面草稿；仅打开或关闭设置后相关浏览位置和草稿仍在。 |
| 非模态与状态一致 | 设置打开时仍能操作主窗口；目录、规则和索引变化反映在两个窗口与菜单中。 |
| 窗口关闭 | 扫描时关闭设置，主窗口与扫描继续；在设置中关闭当前窗口只关闭设置；关闭主窗口或执行退出动作退出应用。 |
| 入口整理 | 正常浏览区不再有常驻设置行和中央设置面板；重扫、失败重试、强读标签和扫描反馈可从约定位置使用。 |
| 引导与恢复 | 首次使用按钮能打开设置添加目录；不可用索引页仍有原因与可操作的新建索引恢复入口。 |
| 保护与错误反馈 | 相关按钮受限时能看见原因，设置操作失败在设置窗口就能读到；忽略规则标明下次扫描生效。 |

## Out of Scope

- Library backup、备份时机和轮换、恢复、恢复前保护份、旧库导入或整理迁移；此前备份延期决定保持有效。
- 搬迁或复制当前索引、更换默认存储目录、数据库结构升级、重做版本兼容策略。
- 菜单栏状态图标、托盘常驻、菜单栏小组件，以及关闭主窗口后继续常驻的生命周期变更。
- 新的全目录扫描命令、周期扫描、目录监视、任务调度系统或扫描算法调整。
- 新的草稿自动保存、退出确认、强制丢弃工作流或统一设置“应用”步骤。
- 重做元数据编辑、封面管理、User tag、Manual collection、合并拆分、Field source 比较或播放功能。
- 在线元数据、Version group 或 Copy 管理、智能合集及音乐库文件写回。
- 全套界面重设计、无关的菜单功能、Windows、新语言、代码签名、公证或托管 CI。
- 为此次文档发布运行实际窗口验收、修改用户正常索引或访问真实 NAS。
