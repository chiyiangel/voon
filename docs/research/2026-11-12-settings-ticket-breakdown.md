# 0003 菜单栏与独立设置窗口工单拆分记录

源规格：[0003 菜单栏与独立设置窗口](../specs/0003-settings-menubar.md)。

用户已于 2026-11-12 以“ok”确认以下六张工单的颗粒度与直接阻塞关系，现按[项目本地 tracker 约定](../specs/README.md)一票一文件发布，初始状态均为 ready-for-agent。实施状态和依赖以[正式工单索引](../specs/0003-settings-menubar/tickets/README.md)为准；下方草案及其 draft 状态保留为发布前的审核历史，父规格保持不变。

## 拆分原则

- 每张功能票交付完整可使用的行为，包含应用操作、状态、界面反馈和对应验证；没有结构变更时不人为增加数据库或核心接口工作。
- 先在现有设置界面补齐保护，再引入非模态设置窗口，避免新入口让未提交编辑或扫描中的资料库切换暴露在缺少保护的路径上。
- 独立窗口票先局部整理共享命令和窗口生命周期，再接入现有入口；后续平台票复用该边界，不各自维护业务逻辑。没有需要 expand–contract 的全项目机械重构，不另设纯基础设施票。
- 两个平台的菜单是各自完整的纵向切片。只有对应平台菜单已经可用，才移除该平台旧的常驻设置行与设置内重扫按钮，保持中间状态始终有入口。
- 菜单、引导与窗口复用既有应用状态层测试接缝；核心公共接口用于配套数据保留回归。原生菜单、窗口、焦点和快捷键进行实际窗口验收，不新增内部或像素测试接缝。
- 每张功能票自带定向验证；最终联验负责完整用户旅程和交错场景，不接收前面各票尚未完成的基本功能测试。
- 同一处代码需要协调修改，不自动构成阻塞边；只列必须先完成的功能依赖。平台环境不足需记录，不能把未验收当作通过。

## 工单草案

### 01 设置操作保护与就地反馈

**What to build:** 用户在现有设置中即可安全增删音乐目录、保存忽略规则和新建索引；扫描中与编辑未提交时的限制有清楚原因，失败无需返回主窗口扫描条才能理解。

**Blocked by:** None (can start immediately).

**Status:** draft，待用户确认拆分后发布。

- [ ] 普通扫描、失败重试和强读标签进行中，目录增删与新建索引均被应用操作拒绝，界面禁用并显示中文原因；查看设置和保存忽略规则仍可用。
- [ ] 限制在提交前复查；先打开的目录选择器或移除确认不能绕过后来开始的扫描。
- [ ] 专辑编辑或封面选择存在未提交草稿时，新建索引被阻止；当前索引、草稿和已保存资料保留。明确保存或取消后才解除对应限制。
- [ ] 设置操作失败和受限原因在现有设置面板内可见；保留主窗口的扫描进度与扫描问题反馈。
- [ ] 配置即时保存；添加目录成功后启动扫描；忽略规则标明“下次扫描生效”，保存不改变当前任务采用的规则，也不自动重扫。
- [ ] 移除目录仍有确认且不删除音乐文件，保留已保存的编辑、User tag 与 Manual collection；新建索引保留原文件及既有位置、版本检查。
- [ ] 通过已有应用状态层和核心公共接口回归证明拒绝后无资料切换、草稿不丢失、规则生效时机和数据保留；实际界面能看见操作原因。

**Demo:** 启动扫描后打开当前设置，尝试增删目录和新建索引均受限；保存忽略规则后本次任务不变，下次重扫采用新规则。另以状态层场景验证编辑草稿存在时拒绝新建索引。

**User Stories:** 6–8、30–40。

### 02 独立设置窗口与共享命令

**What to build:** 现有设置入口及平台快捷键打开共享当前资料库的独立窗口；重复打开只聚焦，关闭设置后仍可继续浏览和扫描。此票交付完整窗口行为，不等待菜单呈现。

**Blocked by:** 01 设置操作保护与就地反馈。

**Status:** draft，待用户确认拆分后发布。

- [ ] 在本切片开始时局部整理应用命令与窗口协调；现有设置入口、关闭操作和设置内按目录重扫复用共享操作，为两平台菜单保留同一执行及可用性边界，不增加新的测试接缝。
- [ ] 设置为非模态单实例；从现有入口或快捷键打开，重复打开聚焦已有窗口；关闭后可重新创建。主窗口仍可操作。
- [ ] 设置显示已有索引路径、目录列表、忽略规则和新建索引操作，使用 01 的保护和就地反馈。
- [ ] 主窗口不再以设置替换中央内容；仅打开、聚焦或关闭设置不重建浏览内容，保留位置、搜索、筛选、排序、选择与编辑、封面草稿。
- [ ] 设置与主窗口共享应用状态和当前索引；配置保存及成功新建索引后显示一致，不分别维护可写库，不因替换资料库状态丢失窗口协调。
- [ ] 修正任意窗口关闭即退出的行为：关闭设置不退出、不停止扫描和后台任务；关闭主窗口或执行退出动作才退出应用。
- [ ] 设置、关闭当前窗口和退出命令分别使用 macOS 的 `⌘,`、`⌘W`、`⌘Q` 及 Linux 的 `Ctrl+,`、`Ctrl+W`、`Ctrl+Q`；按当前焦点窗口关闭。
- [ ] 本票暂保留常驻设置入口和设置内重扫按钮；后续各平台菜单可用时再移除，避免中间状态丢失操作入口。
- [ ] 状态层回归证明业务状态、草稿与索引保护延续；实际窗口验证单实例、焦点、主窗口可操作及关闭后扫描继续。Linux 未取得窗口证据时如实记录，交由 04 验证平台适配。

**Demo:** 选中 Album 并滚动列表、打开编辑草稿，用快捷键打开设置，再次打开只聚焦；关闭设置后原草稿和浏览位置仍在。保存草稿后开始扫描，再打开并关闭设置，进度继续更新。

**User Stories:** 4、5、10–19、21、27。

### 03 macOS 原生菜单与目录重扫

**What to build:** macOS 用户从屏幕顶部原生菜单管理设置与应用窗口，并通过资料库菜单选择一个音乐目录进行增量重扫；主浏览区释放设置行占用的空间。

**Blocked by:** 02 独立设置窗口与共享命令。

**Status:** draft，待用户确认拆分后发布。

- [ ] 屏幕顶部原生应用菜单提供“Voon → 设置…”及退出动作，并提供关闭当前窗口命令，复用 02 的窗口和共享操作。
- [ ] 菜单显示 `⌘,`、`⌘W`、`⌘Q` 等对应快捷键；主窗口或设置窗口获得焦点时均按约定执行，重复打开设置不产生第二个窗口。
- [ ] “资料库 → 重新扫描”按当前 Library root 列出明确目录；选择后仅该目录增量扫描，进度和取消仍在主窗口。
- [ ] 菜单随目录增删及成功新建索引更新；不存在、已移除、无可用目录或当前受限的操作不发起扫描，执行时复查共享保护。
- [ ] macOS 菜单可用后，移除本平台常驻“设置 · 音乐库”行和设置内重扫按钮；设置配置、失败重试与强读标签仍从各自约定位置使用。
- [ ] 不新增扫描全部目录命令、菜单栏状态图标或后台常驻行为；不改变音乐文件和增量读取规则。
- [ ] 状态层验证目标目录与保护，复用真实 worker 读取数回归；实际 macOS 窗口验证菜单可见、动作、快捷键、焦点和旧入口移除。

**Demo:** 添加两个 Library root，从顶部菜单选其中一个重扫，确认只扫描该目录；从“Voon → 设置…”打开并重复聚焦设置，使用关闭当前窗口命令后主窗口和扫描继续。

**User Stories:** 1、3、18、20、22–24。

### 04 Linux 可见菜单与目录重扫

**What to build:** Linux 用户从窗口顶部实际可见的菜单管理设置与应用窗口，并明确选择音乐目录增量重扫；与 macOS 使用同一套业务操作。

**Blocked by:** 02 独立设置窗口与共享命令。

**Status:** draft，待用户确认拆分后发布。

- [ ] 应用窗口顶部实际显示可操作菜单，提供设置、关闭当前窗口、退出和按目录重新扫描；仅调用保存菜单配置的接口不算交付。
- [ ] 菜单动作复用 02 的共享命令、窗口协调和应用状态，不建立独立的 Linux 配置或扫描实现。
- [ ] 显示并支持 `Ctrl+,`、`Ctrl+W`、`Ctrl+Q`；设置窗口重复打开时聚焦，关闭当前设置窗口不退出或停止扫描。
- [ ] “资料库 → 重新扫描”使用当前 Library root 列表，单个选择只影响该目录；来源变化后菜单更新，受限和过期动作不能绕过状态保护。
- [ ] Linux 菜单可用后，移除本平台常驻设置行和设置内重扫按钮；保留主窗口扫描反馈、失败重试与专辑强读标签入口。
- [ ] 菜单在正常浏览、首次使用及索引不可用状态下可达，不被主内容区的不同分支隐藏。
- [ ] 应用状态层回归证明目标目录、配置一致性和保护；Linux 构建及实际窗口验证可见菜单、快捷键、单实例和关闭规则。分别记录 X11 与 Wayland，未验证项不计为通过。
- [ ] 平台差异留在应用边界，不修改核心数据库结构或引入托盘常驻。

**Demo:** 在 Linux 从可见菜单打开设置，重复命令聚焦；选择一个目录重扫后关闭设置，主窗口继续反馈进度，再由菜单重新打开设置。

**User Stories:** 2、3、19、20、22–24。

### 05 首次使用与索引故障引导

**What to build:** 没有音乐目录的用户可从主窗口引导直接进入设置；索引打不开时仍有原因和可执行的新建索引恢复路径，不依赖寻找菜单才能继续。

**Blocked by:** 02 独立设置窗口与共享命令。

**Status:** draft，待用户确认拆分后发布。

- [ ] 空资料库页面提供“添加音乐目录…”引导，通过共享命令打开或聚焦同一个设置窗口，由设置完成添加；不保留并行的中央配置流程。
- [ ] 继续使用既有启动参数或环境设置提供的建议目录；添加后即时保存并开始扫描，主窗口从空库进入相同资料库的浏览与进度状态。
- [ ] 索引不可用时继续展示中文原因及已知路径，保留“新建索引…”可操作入口；取消和失败不切换资料库，成功后使用独立新库并保留原文件。
- [ ] 恢复入口与设置内新建索引遵循同一保护，不绕过任务、草稿、版本或索引位置限制。
- [ ] 设置已打开时完成恢复或添加目录，设置、主窗口与后续菜单读取同一份新状态，窗口协调与重复聚焦继续有效。
- [ ] 通过已有应用状态层和核心公开操作验证隔离索引的新建、失败与重开；实际窗口走通首次使用和故障恢复，并在相应窗口读到错误。

**Demo:** 用隔离空索引启动，从引导进入设置添加目录并看到扫描；再用不可识别的隔离索引启动，从故障页新建独立索引，随后进入同一设置窗口添加目录，原文件保持不变。

**User Stories:** 28–30、32、38、39。

### 06 完整用户旅程与平台联验

**What to build:** 用户可以完整走通启动、设置、浏览、扫描、编辑保护和索引恢复流程；修正集成后出现的交错问题，交付可复核的自动化与平台验收记录。

**Blocked by:** 03 macOS 原生菜单与目录重扫；04 Linux 可见菜单与目录重扫；05 首次使用与索引故障引导。

**Status:** draft，待用户确认拆分后发布。

- [ ] 以前五票各自完成的验证为基线，联合检查菜单、快捷键和引导只打开一个设置窗口；正常浏览不再有常驻设置行、中央配置面板或设置内重扫入口。
- [ ] 选中 Album、滚动、搜索和筛选并打开专辑或封面草稿，再打开、关闭和重新打开设置，浏览位置与草稿保持；尝试新建索引被阻止，明确保存或取消后才可继续。
- [ ] 在目录选择或移除确认与另一窗口启动扫描交错时保护仍有效；扫描中关闭设置、保存忽略规则、取消任务及再次打开设置后状态一致，不产生重复扫描或无声切库。
- [ ] 新建索引成功后主窗口、设置与目录菜单更新；取消、失败和不可用索引恢复均遵循原文件保留规则，配置持久化经重开验证。
- [ ] User tag、Manual collection、编辑、Cover 选择、合并拆分、Field source 比较、Needs attention 重试和专辑强读标签继续在原有内容上下文使用。
- [ ] 使用临时音乐目录和隔离索引检查文件只读及人工整理保留，不修改用户正常索引；不引入备份，也不重做约 20 张真实专辑验收。
- [ ] 工作区测试、严格 Clippy、格式与差异检查通过；实际记录 macOS、Linux X11、Wayland 构建及窗口结果，未验证的平台明确保留未完成状态，不以状态层或其他平台替代。
- [ ] 将本规格的实现与验收结果单独记录，不关闭或改写 0001、0002 已有的未完成外部验收，也不修改父规格来迁就实现。

**Demo:** 从隔离空库启动，配置两个目录，菜单选择其中一个增量扫描，打开并关闭设置确认任务继续；编辑 Album 后验证新建索引保护，再完成独立索引恢复并重开验证配置，逐平台核对相同行为。

**User Stories:** 9、25–27；完整旅程联验 1–40。
