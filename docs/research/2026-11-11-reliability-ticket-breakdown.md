## 拆分原则

每张功能票包含必要的数据持久化、公共接口、应用状态、界面和两个既有测试接缝上的验证。不能把单独建表、改接口或做界面当作一张完成的功能票。

没有发现需要跨整个项目机械迁移且无法保持中间可用的宽重构，因此不单列基础设施或 expand–contract 工单。相关模块的局部收口在对应切片开头完成，保持已有调用可用，避免先做一轮没有可演示结果的重构。

候选比较先交付标题与年份的完整来源链，再扩到全部现有字段；缩略图先持久化当前请求的封面，再交付全库后台覆盖与状态。这两条都按可使用的行为切分。

代码位置重叠不构成阻塞边；共享改动需要协调，但只把真正依赖前置行为的票列为 Blocked by。每张功能票先完成自己的回归和状态验证，最后一票不能代替前面各票的测试。

## 工单草案

### 01 局部扫描失败保留完整 Album

**What to build:** 某个目录或 Disc 暂时不可读时，Voon 保留上次完整 Album，明确显示本次读取不完整；其他结构完整的 Album 仍可更新。首次发现但不完整的位置进入 Needs attention，不作为完整专辑发布。

**Blocked by:** 无，可立即开始。

**Status:** draft，待确认后发布。

- [ ] A 不可读、B 有正常变化时，A 保留全部 Disc、Track 和已知资料，B 的新增与真实移除正常更新。
- [ ] 多碟 Album 缺一张 Disc 的观察时不发布缩水结构；目录失败与标签、封面失败的含义分开。
- [ ] 首次发现即不完整的位置显示路径、阶段、原因与可查询的问题记录，普通列表不会把部分曲目当成完整 Album。
- [ ] 问题状态经索引重开保留；后续完整重扫成功后更新资料并解除对应错误。
- [ ] 列表、详情、Collection 导航和计数保持一致，人工编辑与路径关联的组织资料不因临时失败丢失。
- [ ] 在 core 公共接口和 GPUI 状态层证明该链路，另以真实目录读取拒绝验证检测边界；不写入 Library root。

**Demo:** 已有 A、B 两张专辑，令 A 或其 CD2 不可读，修改 B 后重扫；A 保留完整旧资料并显示错误，B 更新；重开后结果相同。

**User Stories:** 3、7–15、21。

### 02 标签失败分类与增量恢复

**What to build:** 一次标签读取失败不会清空上次成功资料，也不会被相同 stamp 的缓存长期阻止重试。普通重扫可在读取恢复后补齐元数据，界面能区分无标签、未支持、暂时失败和解析失败。

**Blocked by:** 无，可立即开始。

**Status:** draft，待确认后发布。

- [ ] 成功有数据、成功无标签、未支持格式、暂时 I/O 失败和解析失败具有可观察的不同结果。
- [ ] 失败记录与上次成功资料分开保留；失败不把已有元数据覆盖成空值。
- [ ] 相同大小和修改时间下，下一轮普通重扫实际重试失败读取，成功后解除错误。
- [ ] 成功且未变化的标签仍复用缓存；未支持格式不进入无限自动重试。
- [ ] 详情或 Needs attention 显示中文路径、阶段和原因，不依赖新增的手动重试按钮才能验证普通重扫恢复。
- [ ] 保留真实读取时间和成功缓存的来源关联，命中缓存不伪造新观察；在两个既有接缝验证关闭重开和恢复行为。

**Demo:** 首次读取失败，保持源文件不变，再恢复读取并普通重扫；底层实际重读一次、资料补齐，第三次未变重扫不再重读成功标签。

**User Stories:** 22–27、30、44。

### 03 CUE 时长与曲目演奏者完整呈现

**What to build:** Virtual track 按已知 CUE 边界显示时长，详情逐轨显示已解析演奏者；即使 DFF 标签不支持也不丢失 CUE 本身提供的资料。

**Blocked by:** 无，可立即开始。

**Status:** draft，待确认后发布。

- [ ] 起点 0、终点 13500 帧的 Virtual track 显示 180000 ms，不依赖标签读取成功。
- [ ] 末轨总长可知时显示剩余时长，不可知时如实显示未知。
- [ ] 两首不同演奏者的曲目在详情各自显示正确演奏者。
- [ ] 公开查询、数据库往返及应用重开后仍保留时长、演奏者和映像/CUE 来源。
- [ ] 默认播放器入口准确说明打开整个映像，不引入定位播放、DFF 属性解析或切分文件。
- [ ] core 与状态层场景通过，并核对实际窗口中时长和演奏者确实被渲染；音乐与 CUE 内容不变。

**Demo:** 打开两轨 DFF 加 CUE，第一轨显示 3:00，末轨总长未知，两个演奏者分别可见；重开后不变。

**User Stories:** 48–54。

### 04 当前 Cover 持久化与离线重开

**What to build:** 现有浏览或封面选择流程成功加载的当前 Cover 写入本机持久缩略图，退出后断开 NAS 仍可显示；自动图和手选图使用同一套关联与失效规则。

**Blocked by:** 无，可立即开始。

**Status:** draft，待确认后发布。

- [ ] 外置图片、内嵌图片及指定内嵌索引都能生成可重开的本地缩略图。
- [ ] 资产完整写入并可读取后才标为已就绪，持久数据及其 Cover 关联经应用重开保留。
- [ ] 已就绪封面在退出进程、断开来源、重新启动后仍可在网格和详情显示。
- [ ] 更换选择或确认来源变化时更新关联；迟到任务不能覆盖较新的选择。
- [ ] 单项读取、解码或缓存损坏不清空 Album、选择或其他资产；无有效缓存时不冒充已就绪。
- [ ] 内存淘汰不删除应保留的持久资产；后台工作有界，产物不写入 Library root。
- [ ] 用真实图片、真实本地存储和重开场景验证，不只让假加载器返回成功。

**Demo:** 浏览几张自动封面并手选一张内嵌图片，待加载成功后退出、断 NAS、重启；这些图片仍能显示。

**User Stories:** 56、59–63、65–67。

**切片边界:** 本票把现有“已请求的封面”流程变为可持久使用；全部未浏览 Album 的后台覆盖和全局进度在 10 交付。

### 05 新建索引与资料库版本保护

**What to build:** 用户可保留原库、从新建资料库扫描；已有未知或较新版本的库得到中文提示，在任何写入性初始化之前拒绝改写。

**Blocked by:** 无，可立即开始。

**Status:** draft，待确认后发布。

- [ ] 新库能创建、扫描、重新打开并继续正常使用。
- [ ] 已有更高结构版本或无法识别身份的库，在写入性初始化及迁移前被拒绝。
- [ ] 拒绝不会改写原库及已有相关文件，也不自动降级、清空或把未知库当成空库。
- [ ] 不兼容提示可见且可理解，说明保留原库、新建索引重新扫描的选择。
- [ ] 旧库文件不因创建新库而被删除或覆盖，不增加旧库迁移和来源补齐流程。
- [ ] core 公共接口验证文件不变与新库往返，应用状态验证相应可见提示和新建流程。

**Demo:** 选择一个未知库或较新库，看到拒绝说明且原文件不变；随后从新库扫描成功。

**User Stories:** 1、2、68–71。

### 06 取消离线与结构整理保持一致

**What to build:** 将完整 Album 发布规则延伸到取消、整根离线、空挂载点以及合并拆分后的重扫，保留原始基线、人工整理和撤销能力，避免过期扫描消息破坏当前状态。

**Blocked by:** 01 局部扫描失败保留完整 Album。

**Status:** draft，待确认后发布。

- [ ] 取消首次扫描保留完整发现部分；取消重扫保留未访问 Album，重开后仍可浏览。
- [ ] 扫描期间根目录消失或设备变化时不清空旧索引；正常根的更新不受另一根失败影响。
- [ ] 曾有内容的根本次为空时继续要求明确确认，确认前不更新完整基线。
- [ ] 不完整范围不推断 Rename candidate，也不污染下一轮完整扫描的改名判断。
- [ ] 合并拆分结果、真实来源、组织关系及撤销记录经局部失败后保持可用。
- [ ] 扫描期间的新人工编辑继续优先，取消、切换任务或移除根之后的过期事件不重新发布旧状态。
- [ ] core 与 GPUI 状态层覆盖取消、离线、重新连接及结构操作交错的可观察结果。

**Demo:** 合并一张多碟专辑后重扫，中途断开或取消，再重开并重新连接；专辑结构和编辑仍在，撤销可用且没有假改名。

**User Stories:** 5、12、15–21、75。

### 07 重试失败项与强制重读标签

**What to build:** 用户可以从失败状态重试相关项，或对选中 Album 强制重读标签；操作有明确进度、有限的一轮工作和取消能力，不影响无关成功资料。

**Blocked by:** 01 局部扫描失败保留完整 Album；02 标签失败分类与增量恢复。

**Status:** draft，待确认后发布。

- [ ] 目录和标签失败记录提供匹配的重试入口，相关 Library root、Album 与阶段明确。
- [ ] 失败项重试不把整个资料库无差别重新读取，成功后对应状态解除。
- [ ] 强制重读绕过选中 Album 的相关标签缓存，其他成功且未变的缓存仍有效。
- [ ] 取消后保留已接受的完整资料；临时失败不清空上次成功值。
- [ ] 每次触发只执行有限一轮，不创建持续监听、定时扫描或无限重试服务。
- [ ] GPUI 状态层验证“操作—实际读取—持久化—状态解除”及取消；所有交互保持中文。

**Demo:** 在 Needs attention 中重试一个已恢复的目录，再对一张专辑强制重读，核对只处理预期范围并能取消。

**User Stories:** 13、23、24、28、29、31、32、72。

### 08 标题与年份的完整来源比较

**What to build:** 先为标题与年份交付完整的标签、CUE、目录候选链：从扫描保存具体来源和观察时间，到详情比较、人工覆盖和恢复自动值，重开后仍可使用。

**Blocked by:** 01 局部扫描失败保留完整 Album；02 标签失败分类与增量恢复。

**Status:** draft，待确认后发布。

- [ ] 标题与年份在入库前不丢弃同来源不同文件的候选，保留源实例、适用范围和真实观察时间。
- [ ] 详情可比较各候选、采用值、自动值及人工值；来源可对应具体文件、CUE 或目录。
- [ ] UserEdit > Tag > Cue > FolderName 不变，来源内部继续沿用既有确定性规则。
- [ ] 人工编辑经重扫保留，恢复自动值不删除候选；空白沿用恢复自动值的现有语义。
- [ ] 来源失败时保留上次成功证据和可理解状态，缓存命中不伪造新读取时间。
- [ ] 数据库及应用重开后离线可查，完整 Album 发布与候选一致，不要求旧库迁移。
- [ ] core 公共查询和 GPUI 状态验证从源值到界面的整条链，不单独交付没有 UI 的候选表。

**Demo:** 标签年份 1999、CUE 年份 1988、目录年份另有信息，详情能比较全部来源；手动修改、重扫、恢复自动再重开，候选仍在。

**User Stories:** 33–41、44、45、47（本票以标题、年份为首个字段范围）。

### 09 全部现有字段的候选与编辑一致性

**What to build:** 将已可使用的候选比较扩到全部十个现有专辑字段，保持离线查询、失败来源保留、人工覆盖及现有浏览组织的一致性。

**Blocked by:** 08 标题与年份的完整来源比较。

**Status:** draft，待确认后发布。

- [ ] 其余现有字段接入同一来源保存、公开查询、详情比较和恢复自动值行为，不新增领域实体或字段种类。
- [ ] 合辑中少数曲目的作曲家、演奏者等候选不因多数值归并而丢失，仍保留具体文件与曲目范围。
- [ ] 默认自动值及人工优先级不变，已保存人工资料经普通和强制重读继续保留。
- [ ] 失败来源沿用上次成功候选及状态，成功重读后更新；重新打开后仍可离线比较。
- [ ] 流派维持仅来自 Metadata tag，乐团没有自动来源时保持未知或使用人工值，不编造资料。
- [ ] 列表、详情、既有作曲家浏览及编辑对同一采用值保持一致。
- [ ] 不引入逐字段来源偏好、显式人工空值、多年份模型、在线查询或批量冲突审阅。
- [ ] 两个既有接缝覆盖全部字段及组织、结构操作回归，必要的真实窗口验收核对候选可读性。

**Demo:** 打开含不同作曲家和演奏者的合辑，所有候选可查；断 NAS、编辑并恢复自动值，重开后来源与选择一致。

**User Stories:** 33–47、75（全部字段范围）。

### 10 全库封面预缓存与失败重试

**What to build:** 将持久封面能力扩到所有已入库 Album，不要求逐张浏览；独立显示预缓存进度，区别无图、未缓存、处理中、已就绪和失败，并能重试失败封面。

**Blocked by:** 04 当前 Cover 持久化与离线重开。

**Status:** draft，待确认后发布。

- [ ] 扫描接受或加载全部 Album 后，当前自动和手选 Cover 都进入后台缓存，不依赖视口请求。
- [ ] 缓存任务有界，不为全库常驻全部解码图像，内存淘汰不删除当前封面的持久资产。
- [ ] 扫描进度与封面进度分开；存在失败或尚未完成时不声称全部封面已就绪。
- [ ] 单项失败显示明确状态，来源恢复后可重试，不必重扫全部音乐。
- [ ] 更换封面、移除根或出现过期任务时，状态和最终图片对应最新有效选择。
- [ ] 未浏览 Album 及超过内存容量的封面，在缓存就绪后退出、断 NAS、冷启动仍可显示。
- [ ] 用真实本地资产和 GPUI 状态证明全库队列、失败恢复及离线加载，另做进程冷启动窗口验证。
- [ ] 不扩展为小册子、原图收藏、历史封面管理或 Library backup。

**Demo:** 不逐张浏览便让一批专辑封面缓存完成，包含一张故障图；恢复来源并重试，再冷启动离线查看未浏览过的专辑。

**User Stories:** 4、55–67。

### 11 故障交错与真实样本联验

**What to build:** 将前面各条已验证的行为放到同一资料库与真实窗口中联验，修正扫描、编辑、候选和封面任务交错时的集成缺口，提供可复核完成证据。

**Blocked by:** 03 CUE 时长与曲目演奏者完整呈现；05 新建索引与资料库版本保护；06 取消离线与结构整理保持一致；07 重试失败项与强制重读标签；09 全部现有字段的候选与编辑一致性；10 全库封面预缓存与失败重试。

**Status:** draft，待确认后发布。

- [ ] 临时故障库覆盖本规格的核心场景，包含局部不可读、相同 stamp 恢复、取消、换封面及过期任务。
- [ ] 使用约 20 张用户认可的真实专辑，覆盖多编码 CUE、整轨、多碟、DSD、混合标签、外置和内嵌封面。
- [ ] 实际窗口确认失败提示、候选比较、逐轨演奏者及离线冷启动封面，不用状态测试代替可见结果。
- [ ] 交错执行扫描、编辑、重试和封面更换后，公开查询、应用状态、导航计数和持久资料一致，缺口在本票修正。
- [ ] 工作区测试、严格 Clippy、格式和差异检查通过，现有浏览、标签、Manual collection、忽略和结构纠错无回归。
- [ ] 音乐库文件集合、内容及修改时间保持不变，本地产物不落入 Library root。
- [ ] 保留 macOS 与 Linux 的构建和平台要求；不可用环境明确记为未验证，不将平台或用户手工验收标为已完成。
- [ ] 不因联验重新引入备份恢复、旧库迁移、在线资料、相关版本或新的测试接缝。

**Demo:** 在一套受控资料库及选定真实样本中演示故障、恢复、重启离线和人工整理全流程，并附各平台的实际验证记录。

**User Stories:** 4、6、73–75，以及前述各功能的交错回归。
